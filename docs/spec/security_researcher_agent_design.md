## 0. 第一原则：思维在 LLM，动手在智能体

**思维能力在 LLM，动手能力在智能体**——两者是平级分工，不是"能力 vs 辅助"。

```
LLM   = 思维能力（推理、判断、决策、生成代码思路）
智能体 = 动手能力（执行工具、跑代码、操作环境）

双向循环：
  智能体 → LLM：组织上下文、描述工具、管理状态、注入经验，让 LLM 思考得更好
  LLM   → 智能体：思考结果（决策、代码、指令），让智能体动手得更准
```

一切设计决策的判据只有一个：**让这个「思维 ↔ 动手」循环转得更好**，而不是"结构多强 / 建模多完备"。任何结构，如果不能让 LLM 思考更清、或不能让智能体动手更准，就是负担。

> 反向理解：不是"把安全研究建模好了、能力就有了"，而是"把思维和动手两个半环组织好，让循环高效转起来"。

## 1. 定位与两大支柱

**定位：原生安全研究员智能体。** 思维在 LLM，动手在智能体——智能体原生具备**动手能力**（工具），LLM 能直接**写原生代码**（思维直接变动手）。

**产品本体 = 安全研究领域的 harness**（2026-08-14 沟通确认）：harness 是「思维 ↔ 动手」双向循环的实现（§7），三大领域支柱——**环境融合**（循环的执行环境，D10–D12）、**原生工具**（循环的动手能力，§1.1）、**原生代码**（思维变动手的最短链路，§1.2）。模型可换（§9 收敛 1 主 1 备选），harness 是常量；界面是人介入 loop 的**控制面**（§8）——全屏 TUI、打磨标准对齐 GUI（D13、D15），控制四要素（看得见/插得进/停得下/批得准）是一等交付。

**目标用户（2026-08-14 拍板）**：二进制研究员、渗透研究员、AI 安全研究员、红队研究员、恶意软件研究员、威胁情报研究员。**我们不做工具仓库，做的是 AI 和安全研究的融合**——智能体的价值不在集成了多少工具，而在 LLM 的思维与安全研究全流程（侦察/分析/构造/执行/评估/沉淀）融合得多深：工具给 LLM 赋能，LLM 原生调用工具，经验在循环里越沉淀越厚（D9）。

两个"原生"是双关：

### 1.1 支柱一：原生安全（Native Security）—— 智能体的动手能力，原生内置

- **五大类工具**（渗透 / 密码 / 白盒 / 二进制 / AI）安装即有，不是装 skill/插件拼上去的；CTF 是场景横切（分解到五大类）。
- **开放能力空间**（漏洞 + 情报是主轴示例）是内核，不是贴片。
- 智能体能**原生驱动**安全研究员的领域工具——IDA/Ghidra 的 headless、tshark、Burp 的 API、调试器——不为它做一层 GUI，直接跟这些工具协作。

### 1.2 支柱二：原生代码（Native Code）—— 思维直接变动手的直通链路

- LLM 写 exp / shellcode / fuzz harness / PoC（C/C++/汇编，不是脚本），智能体编译、运行、调试。
- 编译-运行-调试闭环（见 §5），是"LLM 思维 → 智能体动手"最短的一条路。

> "原生"双关：原生安全 = 动手能力原生（工具内置）；原生代码 = 代码原生（native code，思维直接落地）。

## 2. 扩展机制与人协作

### 2.1 扩展入口 = MCP 外挂工具 + skills + subagent

"原生"之外的一切扩展，**统一收口到 MCP + skills**——研究员自己加的、别人造的现成 MCP server 和 skills，都走这两个机制。给 LLM 加能力，**不需要 UI**：

- **外挂工具**：非原生内置的新 MCP / CLI tool。
- **skills**：新的编排/方法，教 LLM 做某件新事。
- **subagent**：子智能体，独立跑某类任务。

研究员可**自造扩展**（MCP server / skills，具体入口随 P 阶段定）；不再有独立插件体系（加密插件已随开源转型移除）。

### 2.2 人协作（人在回路才需要，极少）

- **共享表面**：聊天 / 终端 / 浏览器（LLM 和研究员在同一表面协作）。
- **领域 GUI**：研究员自己用的成熟工具（IDA / Wireshark / Burp / 调试器），ZhiShi 不重做，让 LLM 用 headless/API 去配合。

## 3. 内核：开放能力空间 + 通用循环（给 LLM 的认知语言）

内核不是锁死流程的规则，是**给 LLM 的认知语言**——让 LLM 理解"安全研究的世界由什么组成、做事的节奏是什么"。LLM 在这套语言上**自主推理**，不是查表执行。

### 3.1 能力空间（开放，漏洞 + 情报是主轴示例）

安全研究员的工作是**开放的能力空间**，不止漏洞和情报，还包括渗透、CTF、密码、白盒、逆向、AI 安全、红队等。漏洞 + 情报是主轴示例（两条链 + 交叉）：

```
漏洞链：漏洞挖掘 → 漏洞验证 → 漏洞分析 → 漏洞利用（利用中暴露新信息反哺）
情报链：情报挖掘 → 情报分析 → 情报关联（关联出新线索反哺）
交叉：情报 ⇄ 漏洞（补丁 diff/新披露喂挖掘；漏洞机理/利用条件反哺关联）
```

### 3.2 通用循环（让 LLM 理解做事的节奏，领域无关）

```
Recon 侦察 → Analyze 分析 → Construct 构造 → Execute 执行 → Evaluate 评估 → Distill 沉淀
     ↑                                                                    ↓
     └──────────────────── 评估结果反哺，迭代回环 ─────────────────────────┘
```

领域无关，覆盖漏洞研究、渗透、CTF、密码、白盒、逆向、情报等全能场景。

### 3.3 任务模板层（把循环实例化到场景，示例）

| 模板 | Recon | Analyze | Construct | Execute | Evaluate |
|---|---|---|---|---|---|
| 漏洞挖掘 | 目标/情报收集 | 代码/diff 定位 | fuzz harness | fuzz 运行 | 崩溃研判 |
| 漏洞利用 | 拿根因 | 原语规划 | exploit | 跑靶场 | flag? |
| 情报关联 | 拿碎片 | 关联研判 | 关联关系 | 验证关联 | 闭环? |
| 渗透测试 | 扫描 | 研判 | payload | 攻击 | 突破? |
| CTF | 读题 | 题型 | 解题代码 | 跑 | 对? |
| 密码 | 拿密文 | 算法识别 | 破解脚本 | hashcat | 解出? |

> 这些是**给 LLM 的参照**，不是强制步骤；LLM 自主决定怎么在循环上走。

## 4. 抽象层：给 LLM 的接口（要轻）

抽象层的角色是"给 LLM 的接口"，不是"能力容器"：

| 形态 | 价值 | 方向 |
|---|---|---|
| 本体（强类型 schema） | 约束 LLM **输出**——漏洞带 bug_class/subsystem/primitive，可校验、少幻觉 | 输出侧 |
| 图结构（关系数据） | 扩充 LLM **输入**——用节点+边存关联，给 LLM CVE↔漏洞↔攻击者的关联视野 | 输入侧 |

- **判据**：哪个让「思维 ↔ 动手」循环转得更好，不是哪个结构更强。
- **原则**：抽象层要轻，够 LLM 理解就行，不为"建模完备"堆结构。
- **落点**：内核层（研究过程）倾向轻量类型化；情报层（知识网络）倾向图结构（数据形态，非界面可视化）；二者靠共享实体打通。MVP 先立轻量类型化，图结构后接。

## 5. 原生代码链路

```
① 内置工具链：C/C++ 编译器(clang/gcc) + 汇编器/链接器 + Python 运行时——在环境类型里（环境一开即有），不装宿主机（D12）
② 编译-运行-调试闭环：写代码（本机工作区，可交互）→ 环境内编译 → 运行 → 看结果/崩溃 → 调试 → 迭代
③ 隔离执行：LLM 写的 exploit 跑在环境里，不裸跑宿主机（隔离天然满足）
④ 原生环境能力（2026-08-14）：Docker / 虚拟机天然对接——环境是全生命周期可操作的：配/跑/看/快照/销毁由 LLM 在 ZhiShi 内驱动，创建权专属人、agent 不得自建环境（2026-08-15 细化，见 D17）；研究主体在环境，用户交互在本机。不造自己的编排层，Docker/VM 就是沙箱
```

## 6. 工具资产：五大类 + CTF 横切（智能体的动手能力）

| 类别 | 代表工具 | 主要服务的能力 |
|---|---|---|
| 渗透类 | nmap/masscan、nuclei、burp/sqlmap、metasploit、hydra、frp/内网代理 | 漏洞挖掘（黑盒）、情报挖掘（主动）、漏洞利用 |
| 密码类 | openssl/cyberchef、hashcat/john、签名验证、密文/密钥分析 | 漏洞分析、CTF crypto、情报分析 |
| 白盒类 | semgrep/CodeQL、污点/数据流分析、SCA 依赖分析、审计辅助 | 漏洞挖掘（源码）、漏洞分析 |
| 二进制类 | ghidra/ida/r2、gdb/lldb/pwndbg、binwalk、pwntools、ROPgadget/ropper | 漏洞挖掘（diff）、分析、利用（贯穿） |
| AI类 | LLM 安全测试（越狱/注入）、AI 辅助代码理解与漏洞定位 | 漏洞挖掘/分析、情报分析（NLP） |
| CTF类 | 场景横切：pwn→二进制、crypto→密码、web→渗透、reverse→二进制 | 分解到上述类 |

接入沿用 cuse/terminator 套路：原生二进制（`__bundled_xxx__` 哨兵）→ 签名/R2 → MCP preset → skills 编排。五大类铺开需**统一接入管线**（批量 + 按类管理）。

## 7. harness：思维 ↔ 动手的双向循环

harness 不是"安全研究调度器"（那是在定义流程），是**「思维 ↔ 动手」双向循环的实现**，三件内建能力：

1. **智能体 → LLM（让 LLM 更好地思考）**——组织上下文、描述工具、管理状态、注入经验，让 LLM 在长时多轮的安全研究里思考更清、看得见全貌。
2. **LLM → 智能体（让智能体更好地动手）**——把 LLM 的思考结果（决策、代码、指令）转成精准的工具调用、代码运行。
3. **蒸馏反馈（让循环越转越好）**——把每次迭代的成败轨迹提炼成经验，反哺回"智能体 → LLM"的组织方式：

   ```
   LLM 尝试拿 flag / 挖洞
     ├─ 失败 → 存轨迹（做了什么、卡在哪、为什么失败）
     └─ 成功 → 存轨迹（什么思路走通、用了哪些工具）
      ↓ 蒸馏：提炼关键经验（漏洞根因、哪条路走不通、哪个工具组合有效）
      ↓ 反哺：组织进下次的上下文/工具描述，让 LLM 不重复踩坑、复用成功路径
   ```

   不是训练替代 LLM，是把 LLM 自己的经验组织回这个循环（思维在 LLM）。

## 8. 交互：CLI 一等（研究员定位），聊天 / 终端 / 浏览器为其表面

> 核心区分：**可视化（画出来展示）≠ 交互（双向操作）**；信息不代表有用，可交互才有用。交互的本质 = 人和 LLM 的双向操作，载体极少。
> **2026-08-14 拍板（D13）**：目标用户是研究员不是小白——研究员住在终端，纯 UI 界面是负担。**CLI + agent，删除 GUI**（不交付=删除，不做多余保留；我们的界面 = CLI 的交互可操作性）：聊天 = `zhishi agent` 交互 loop（含审批终端确认）；终端 = 研究员自己的终端 + `zhishi term`（看进环境、可接管）；浏览器 = CDP 驱动用户系统浏览器（登录态共享保留且更原生）。Tauri 壳转为无窗口后台宿主（Rust 层机制全保留——删的是界面不是宿主）；搭子降为状态行/通知（§8.5 状态机逻辑保留、呈现层换掉）。**2026-08-15 定死：明确不需要 GUI，不设恢复路径**——dogfood 证伪信号触发的是 TUI 交互形态的重做，不是 GUI 回归。

### 8.1 共享表面（LLM + 研究员协作）

| 载体 | 承载的安全研究交互 |
|---|---|
| **聊天** | 下达任务、反馈纠正、讨论思路、确认结论 |
| **终端** | SSH 远程靶场、gdb 调试、r2 逆向、跑任意 CLI 工具（研究员看着敲 + 自己敲 + 接管） |
| **浏览器** | 查 CVE、看补丁 diff、Web 渗透、情报检索（登录态共享） |

### 8.2 领域 GUI（研究员自己用，成熟外部工具，不重做）

IDA / Wireshark / Burp / 调试器 GUI —— 研究员在自己熟悉的 GUI 里做"需要人判断"的交互；LLM 用 headless/API 配合（ghidra headless、tshark、curl）。

### 8.3 可视化 = 展示，不是交互

关联图 / 拓扑 / 时间线等，画出来给人一眼看懂结构（前端常规渲染），交互走聊天 / 终端。

### 8.4 结论

交互需求 = **说、敲、点**三件事（聊天 / 终端 / 浏览器）+ 领域 GUI，全部以 CLI 形态承接（D13）：`zhishi agent` / `zhishi term` / CDP 系统浏览器。可视化是展示，不是交互系统。

### 8.5 搭子：安全研究员专属

状态机：忙/闲/提醒 → 「场景 × 循环状态」（如「漏洞利用·执行中」），叠加「有 flag / 根因待核对」等关键事件。认知换成安全语境；人格保留「直接、不编造、纠正即改」+ 安全研究员语感。

## 9. 减法 + 模型

### 减法（砍产品功能，保留核心能力）

**砍（产品功能）：**
- IM Bot 全家 + 应答中心（`im:permission-request` 人工代回）
- 通用生产力 skills（docx/pdf/pptx/xlsx/apple-notes/apple-reminders/bird/imsg/nano-pdf/peekaboo/summarize/remotion）
- 多模型 Provider、gemini-image/edge-tts、需求单、Team Hub 残留
- 造能力（capability-forge）、技能市场/安装/skill-creator、MCP 配置面板、想法收集

**砍掉后统一收口：** 扩展机制 = 原生 + MCP / skills；技能 / 工具扩展的散落功能砍掉，统一走 MCP server 与 skills（研究员可自造）。

**留：** 多 Tab、终端、浏览器、任务中心、记忆（含蒸馏弧）、定时任务、搭子、Panel API；download-anything、github、AppCraft（terminator/cuse）。

### 模型

收敛到 1 主（deepseek-v4-pro）+ 至多 1 备选，砍「10+ Provider」卖点。专属调优 = 上下文组织 + 工具描述 + 状态管理 + §7 蒸馏闭环反哺（让 LLM 思考得更好，不是单一提示词）。

## 12. 已确认的边界判断（区分/纠偏，随对齐持续累积）

**思维与结构**
1. 思维在 LLM——结构（状态机 / 本体 / 图）不产生思维，只是让「思维 ↔ 动手」循环转得更好的手段。
2. 内核要抽象、不写死规则——能力空间 / 通用循环是给 LLM 的认知语言，不是锁死流程的规则。

**原生 vs 外挂**
3. 原生工具（安装即有的二进制，LLM **调用**）≠ 原生代码（LLM **写**，智能体**编译、运行**）。
4. 两个"原生"：原生安全 = 动手能力原生（工具内置）；原生代码 = 代码原生（native code，思维直接落地）。
5. 插件（外挂工具 + skills + subagent）= 外挂扩展；原生（内核）≠ 插件（扩展）。
6. 协作是本体——不是把工具打包进智能体，而是让 LLM / harness / agent / subagent 与工具协作：发现环境里有什么、描述给 LLM、让命令原生可跑、用 skill 教会、用蒸馏沉淀工具经验。打包只限环境基座（工具链 + Python）与少数有状态 MCP 工具。
7. 环境是协作对象，也是**研究的主体**——安全研究员在特定环境（容器 / VM / 靶场 / 目标网络）里做研究，宿主机只是交互面。**环境是可操作的**：全生命周期（配/跑/看/快照/销毁）由 LLM 在 ZhiShi 内驱动，创建权专属人（agent 不得自建环境，见 D17）；工具配合在环境里（含编译工具链），不在本地。核心动作是把能力**赋能到环境中**（环境类型 = Dockerfile + 初始化脚本 + skill，把干净环境变成可用研究环境）；不造自己的编排层，Docker/VM 就是沙箱。

**交互**
8. 插件 / skills 是给 LLM 的（不需要 UI）；交互 UI 是给人的——两回事。
9. 可视化（画出来展示）≠ 交互（双向操作）；信息不代表有用，可交互才有用。
10. 工具分两类：需要人在回路实时交互的（少数）→ 共享操作台；不需要的（多数）→ MCP/CLI。
11. 领域 GUI（IDA / Wireshark / Burp / 调试器）是研究员自己的成熟工具，不重做；LLM 用 headless/API 配合。
12. 交互载体 = 聊天 / 终端 / 浏览器（共享）+ 领域 GUI（研究员自己），不新增交互系统。
13. 图不是"系统"，是"界面上画出来的可视化"（展示），交互走聊天 / 终端。

**范围**
14. 能力空间是开放的——安全研究员的工作不止漏洞和情报，还包括渗透 / CTF / 密码 / 白盒 / 逆向 / AI 安全 / 红队等；漏洞 + 情报是主轴示例，不是封闭边界。
15. 「漏洞挖掘」= 技术性挖洞（fuzz/审计/diff 找 0day 或 1day），搜集已披露漏洞归情报侧。
16. 情报链 = 独立产出 + 喂漏洞链，两者都有（主轴示例之间的交叉）。
17. 主线权重不锁死，用分阶段依赖关系自然展开。

**价值与形态**
18. 安全研究赢在价值层，不在交互层——价值锚点是消灭**研究前期的消耗**（环境准备地狱、工具链碎片化、重复劳动）；价值跟着能力走，不跟着界面走（2026-08-14）。
19. 消耗分三层，可插件化程度不同：①环境/工具准备（可能力化外溢）②研究执行编排（harness 活，通用 agent loop 只能消灭一半）③认知/方法论（完全是 harness 层安全原生设计）——所以主体必须是自己的 harness，MCP/headless 是能力外溢渠道（D-T7），不是主形态。
18. 目标用户 = 二进制 / 渗透 / 白盒审计 / AI 安全 / 红队 / 恶意软件 七类研究员（情报 D29 横切、CTF D30 补充）；做的是 AI × 安全研究的融合，不是工具仓库——评判任何功能先看它让哪类研究员的「思维 ↔ 动手」循环转得更好。
