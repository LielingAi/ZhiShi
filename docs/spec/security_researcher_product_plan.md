## 1. 产品定位

**一句话：安全研究领域的 harness。**

harness = 「思维 ↔ 动手」双向循环的实现：LLM 负责思维（推理、判断、决策、写代码），智能体负责动手（执行工具、跑代码、操作环境），harness 是让这个循环在安全研究场景里转得最好的那套机制——组织上下文（让 LLM 思考更好）、精准执行（让智能体动手更准）、蒸馏反馈（让循环越转越好）。

**模型可换（kimi / deepseek 等，`zhishi model set-key/set-default`），harness 是常量。** 我们不是工具仓库，也不是给通用 agent 加安全插件——产品是 AI × 安全研究的融合，价值锚点是消灭**研究前期的消耗**：环境准备地狱、工具链碎片化、重复劳动。

三大领域支柱：

| 支柱 | 含义 | 一句话 |
|---|---|---|
| **环境融合** | 循环的执行环境 | 容器/VM/靶场是研究的主体所在，全生命周期在产品内驱动 |
| **原生工具** | 循环的动手能力 | 安全工具 100% 跟着环境走，环境类型=基底+初始工具包，能力集合由现场推导（1.3.7 修订） |
| **原生代码** | 思维变动手的最短链路 | LLM 直接写 C/汇编/exploit，环境内编译-运行-调试闭环 |

## 3. 产品形态

**GUI 主窗口 + CLI**（1.3.9 起 TUI 退役；本节 D13/D15 的 TUI 决策为历史，实质原则保留）。

- **交互三件套**（GUI 形态承载同一原则）：环境侧栏（运行中/已停止/本机已有 + 新建向导）+ 主交互流（块化渲染/流式/Esc 中断/越界确认/决策面板）+ 常驻全局状态区（并发 loop/环境/任务一览，搭子「场景 × 循环状态」的落点）；1.4.4 起主区分屏——左屏对话流（过程）、右屏研究档案（成果）。
- **打磨标准 = 别人的 GUI 设计标准**——磨控制可操作性（控制四要素：看得见/插得进/停得下/批得准），不是视觉花哨；手感基线 = kimi-code / Claude Code / Codex CLI。
- **删的是界面不是宿主**：Rust 层（sidecar Owner / Panel API PTY / CronTask / 统一日志）转后台宿主保留，GUI webview 只是新表面。
- **跨 harness 关系：不融合、不委派**（D16）——与 Codex/Kimi Code 等各自独立运转，共享工作区即协作面。
- **D13/D15 历史注记**：2026-08-15 曾定死「CLI + 全屏 TUI、GUI 不做不设恢复路径」——1.3.x 交互形态评审翻转：TUI 承载不了研究结构展示（dogfood 证伪信号 D21 兑现），决策改为 GUI 为主交互面（1.4.0 正式发版），决策原文见文末记录。

## 4. 产品流程

### 4.1 首次启动（一次性，目标 < 10 分钟）

```
安装包 → 首次启动 → bootstrap 并行检测 docker / 虚拟机（VMware Workstation / Hyper-V / VirtualBox）
  → 缺失则引导安装/启用（用户只看进度，不操作）
  → 登录模型 → 完事
```

**没有"装工具"这一步**——工具全在环境类型里，用到哪个环境才构建哪个。

### 4.2 一次研究的完整流程

```
① 起会话    打开 GUI 主窗口（`zhishi agent` TUI 入口已随 1.3.9 退役）
② 选环境    环境选择器（强制第一步，人选）：运行中环境 / 环境类型新建（D27：无「仅工作区控制面」）
③ 下任务    自然语言 + @ 引用环境内对象（样本/补丁/二进制直接进环境）
④ 环境就位  agent 驱动环境配/跑（构建自动化）；环境出现在状态区
⑤ 研究进行  agent 写代码（环境内）→ 环境内编译/运行/调试 → 迭代
            研究员只做三件事：看（输出+状态区）、纠（随时打字）、断（Esc）
⑥ 唯一打断  越界审批：写宿主 / 用本机凭据 / 改网络策略 / 销毁有成果环境
⑦ 后台分叉  长任务（fuzz 等）→ subagent 接走，状态区多一行，主线继续
⑧ 出成果    flag/根因/PoC 留环境（产出过界提取或快照），agent 回报结论 + 文件指针
⑨ 收尾沉淀  环境销毁（默认一次性）或快照保留环境；蒸馏弧后台沉淀经验
```

**跨天续作**：resume 会话 → task.md 状态卡 + 研究记忆注入 → 环境从快照恢复 → 昨天的一切原地复活，死路不重踩。

**中断成本分级**：Esc（停动作）< 纠偏（改方向）< fork（回思路）< 快照回滚（回环境）< attach 接管（自己动手）。

## 5. 产品模型：三个安放规则 + 环境主权

```
环境  = 研究的主体（一次性，可快照可销毁；docker/VM 双原生基底 + SSH 靶场）
工具  = 环境的居民（100% 在环境，无例外不分居；环境类型=基底+初始工具包）
代码  = 环境的居民（D27：研究对象全在环境内；产出过界提取或快照保留环境）
宿主  = 只有三样：控制面（LLM/harness/共享表面）+ 环境接入件 + 应用运行时
```

> **2026-08-26 修订（1.3.7 场景 3 拍板，B 方案）**：「环境类型即工具清单」细化为「环境类型=基底+初始工具包」——环境的能力集合由**现场推导**（配方绑定域 ∪ 工具探测域，环境里实际装了哪些已知工具就是什么能力），域切换在推导集合内裁决、集合外不切；配方绑定=展示/构建来源，不进域裁决（1.3.8 多配方同口径）。用户不声明、不维护能力。

**环境主权模型（D17）**：

| 动作 | 谁做 |
|---|---|
| 选（初始环境） | 人，强制，会话第一步 |
| 建 | **只有人**——一键发起、构建自动化；agent 需要时只能请求 |
| 配/跑/看/快照 | agent 全自动 |
| 销毁 | agent 驱动；有成果环境销毁要人确认 |
| 界内一切操作 | agent 全自动，零审批 |

**环境的存在性归人，环境之内的运转归 agent。**「用户零操作」（D12）= 零动手、有主权。

## 6. 安全模型（D14：边界安全 + 留痕，不是操作审批）

研究主体在一次性隔离环境里——跑恶意样本、打 exploit 就是研究目的本身，**边界之内不需要任何审批**。安全落在边界上：

1. **保护本机**：环境默认摸不到宿主文件系统（挂载控制）、宿主凭据绝不泄进环境、环境→本机写入受控；
2. **出向控制**：网络出站策略（样本不能回连）、产物提取检查——能离开环境的东西是唯一真风险；
3. **环境卫生**：默认一次性、用完即毁、快照回滚、无残留；
4. **供应链完整**：镜像/工具签名校验（分层信任根）、凭据外部引用（keyPath/passwordRef）；
5. **留痕而非审批**：环境内全程静默记录，可复现、可审计。

**审批只剩一件事：跨越边界的动作。** 恶意样本操作硬闸强制 env≠host（边界规则，不是审批）。

## 7. 经验沉淀（蒸馏反馈）

- **research_events**：结构化成败信号（task_kind/outcome/bug_class/summary/trajectory_ref），LLM 自助记录 + 确定性钩子（编译退出码/崩溃信号/flag）。
- **分域蒸馏弧**：经验按研究域成弧（二进制的 fuzz 经验和情报的关联经验不混压），蒸馏产物下次会话注入反哺。
- **状态外置**：研究状态卡（已验证事实/当前假设/死路清单/当前阶段/环境清单）持久化在环境内 task.md；死路清单永留（防重踩 + 蒸馏原料）。
- **复利逻辑**：经验沉淀跟着 loop 走——这是"必须是自己独立 harness"的最硬理由（D16 的根基）。

---

## 8. 内核认知（给 LLM 的语言，不写死规则）

- **能力空间**（开放）：漏洞链为主轴示例，威胁情报是横切层（D29）；渗透/CTF/密码/白盒/逆向/AI 安全全覆盖（红队暂缓）；
- **通用循环**：Recon 侦察 → Analyze 分析 → Construct 构造 → Execute 执行 → Evaluate 评估 → Distill 沉淀，评估反哺迭代；
- **任务模板参照**：漏洞挖掘/利用、情报关联、渗透、CTF、密码等场景的循环实例化——给 LLM 的参照，不是强制步骤。

## 9. 边界与不做

- **不做 U 盘/便携场景**（D7）；不考虑分发体积/FAT32/离线更新约束。
- **首批不提供插件**（D8）——能力全部内置（bundled 环境类型 + system skills + 内置 subagent + harness 内建）；插件机制存量保留。
- **不把工具打包进产品**（D9）——本体是协作：发现→描述→调用→教会→反馈。
- **不重做领域 GUI**（IDA/Wireshark/Burp/x64dbg 是研究员自己的工具，LLM 走 headless/API 配合）。
- **不与其他 harness 融合或委派**（D16）。
- **不做 GUI**（D13，Tauri 壳转无窗口宿主）。
- **减法已落地**：IM 全家/应答中心、通用生产力 skills、多模型 Provider、需求单、想法收集、造能力、技能市场、MCP 配置面板等已删除（10 万+ 行，见技术方案 §10）。

## 10. 模型策略

供应商可换（kimi / deepseek 等），`zhishi model set-key/set-default` 配置密钥与默认模型；出厂收敛 **1 主（deepseek-v4-pro）+ 至多 1 备选**。专属调优不靠单一提示词，靠 harness 四件套：上下文组织 + 工具描述 + 状态管理 + 蒸馏闭环反哺。

## 13. 证伪与可逆性

- **GUI 定死不做**（D13，2026-08-15 定死）：明确不需要 GUI，不设恢复路径——原可逆性声明撤销。dogfood 证伪信号（D21：控制四要素任一在 TUI 反复做不到、被迫绕出产品完成核心 loop ≥2 次，或研究员明确要界面）触发的是 **TUI 交互形态的重做**，GUI 不在选项内。
- **第一个 dogfood 场景**（D21，2026-08-15 拍板）：**CTF pwn 题**（闭环最短，一把验 adopt/实机冒烟/TUI 手感/蒸馏闭环）；第二个 = CVE 复现。
