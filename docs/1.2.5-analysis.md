# 1.2.5 分析：原生工具选型——三路研究结论

> 2026-08-22。基于现状摸底（9 配方 × 32 份真实轨迹 × 28 条研究事件）。
> 用户拍板的三条方向：①选型把 LLM 认识的工具选进去；②工具优化 + 模型理解；
> ③每个配方 docker + VM 双形态都支持。

## ① LLM 认知普查（逐配方逐工具，轨迹实证 + 模型知识判断）

判据：模型训练知识里有没有这个工具（认识 = 知道用法 + 读懂输出）。

| 配方 | 全认识（零教学成本） | 半认识（需 skill 教） | 备注 |
|---|---|---|---|
| pentest | nmap/masscan/ffuf/gobuster/sqlmap/hydra/nc/socat/curl | — | 选型最健康；缺 wordlists（skill 引用了没装的字典，1.2.5 必修） |
| pwn | gdb/pwndbg/pwntools/ROPgadget/ropper/checksec/socat/nc | — | 全主流，选型最健康 |
| fuzz | AFL++ 全家 | — | 认识但零实战背书 |
| rev | gdb/binutils(objdump/readelf/nm)/java | Ghidra analyzeHeadless（headless 用法半熟） | |
| dev | clang/gcc/g++/make/cmake/gdb/lldb/git/python3 | — | |
| code-audit | rg/pip-audit/semgrep | osv-scanner（知名度中）、ctags（universal 变体用法一般） | 播种态还缺 osv-scanner（双缺） |
| ai-security | — | **garak / promptfoo（认识度低）** | 实证：dogfood 弃 garak 用手工探针且效果更好 |

**结论**：整体选型健康——主流工具全是 LLM 老熟人；真正需要处理的是
ai-security 的 garak/promptfoo（认识度低 + 实战输给手工探针）和少量半熟件
（osv-scanner、analyzeHeadless）。**「LLM 认识」这条判据追溯成立**：
1.1.8 时 agent 弃 garak 选手工就是这条判据的自发执行。

## ② 工具优化 + 模型理解（跟着①走）

- 半认识工具 → skill 里补「用法惯例 + 输出怎么读」（analyzeHeadless 的
  调用形态、osv-scanner 的输出字段、garak 的探针族语义）。
- 输出不友好工具 → 教学里给「LLM 友好用法」：`nmap -sV` 慢（1.1.8 已教
  手工 banner）、gdb 用 `-batch -ex`（轨迹实证 agent 自发这么做的，
  应写进 skill 固化）、garak 输出形态要先实测再定信号规则（ai-security
  域信号现在按假设的 `\d+ FAIL` 写的）。
- 模型理解侧：配方 SKILL.md 正文（工作流/降级路径）现在不进 prompt
  （recipes.ts 只解析 frontmatter）——发现环只有裸工具名。这是「模型理解」
  链路的最大缺口：**配方正文要进能力清单**（或至少进发现环）。

## ③ 配方双形态（机制分析结论）

**前提纠正**：fuzz↔fuzz-vm、pwn↔pwn-vm 已是成对双形态；真缺口 = 5 个
docker-only 配方缺 VM 版（pentest/code-audit/dev/rev/ai-security），
VM-only 缺 docker 版的为 0。`-vm` 后缀配对命名已是定例。

**形态差异要点**：docker = Dockerfile RUN 装工具（root、构建期）、镜像即定型、
无快照；VM = setup.sh 在 guest 内装（sudo + PEP 668 + 镜像回落，全是
pwn-vm 的实机踩坑注释）、快照定型。转换的主料可复用（tools 声明/自检/skill
工作流），要重写的是安装段和网络/快照语义。

**建议（分析方）**：双形态做 pentest（独立网络命名空间对渗透有真实语义价值）
和 rev（挨着 detonate 工作流）；**dev / ai-security / code-audit 不做随包
VM 版**（dev 的 VM 版是负资产——40GB 模板做通用编译不值；ai-security 打
远程端点无隔离需求；code-audit 弱隔离），配方结构两态同构的能力留着，
用户需要时自造。

**toolCheck 挂点**（双形态后缺口会放大）：①adopt/build 收尾、快照之前跑
自检（缺工具不冻结快照）②env up 回写条目时泛化 runRecipeToolCheck 收
EnvironmentEntry（注意非交互 ssh 无 ~/.local/bin 的 PATH 坑）
③domain/check 的 docker-only 过滤扩到 VM。

**成本**：写文件便宜（S≈半天/M≈1天/L≈1.5天），贵在实机 dogfood——
每个新 VM 配方约 1-2 轮 adopt/build 实机迭代（autoinstall 20-45 分钟/轮）。
pentest-vm(S) + rev-vm(L) ≈ 2 人日 + 实机窗口。

## 附带风险（要提前定的）

配方播种 seed-if-missing 永不覆盖——双形态 rollout 期间修老配方（如
pwn-vm 的 checksec `|| true`），老用户拿不到修正。这个「配方修正无法触达
老安装」的策略缺口需要单独决策（bump 只补缺失不覆盖的现状）。
