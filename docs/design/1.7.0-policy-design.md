# 1.7.0 auto-loop 策略系统设计

> 状态：定稿待评审
> 范围：auto loop（loop/auto-run.ts）的治理层重构 + CLI 入口补口 + 同环境互斥闸 + 僵尸愈合
> 前置设计：auto-loop-design.md（1.4.1）、discovery-campaign.md（1.6.8）

## 1. 背景与问题（轨迹/讨论共识）

1. **暂停点全人肉闸**：auto loop 有 5 个暂停点（verdict / decision / stall / repeated-failures / budget），全部等人在场，无任何超时兜底——无人值守时 run 无限期停滞。
2. **CLI 无入口**：`zhishi auto-run <action>` 通用管线路由可达，但 `buildRequestBody` 无 auto-run 分支，`criteria`（数组）与 `budget`（对象）载荷形状发不起来，start 必败。
3. **同环境并行污染**：单实例闸只卡 workspace，不同 workspace 的多个 run 可绑同一 envKey——快照/文件/进程状态互相踩踏，结论互相作伪。
4. **僵尸记录**：sidecar 重启后 `paused` 态记录无恢复通道（内存 runner 消亡，budget/verdict 端点均拒绝），只能 clear。
5. **终审无下游消费方**：一次性 auto run 终态后无法续跑，「人已背书」没有系统状态可承载——背书是人读报告后的外部判断。

## 2. 目标

策略文件（YAML）成为 run 的**唯一治理来源**；run 全程自主，无弹窗、无交互、无续跑重入。人与 run 的接口只有两处：**开局写策略，结束读报告**。

**CLI 与 GUI 不互通**：GUI 保留原生交互流程（现状，零改动）；策略系统服务于 CLI / 无人值守。策略 schema 中**没有 ask 枚举**——不为 CLI 构造任何交互逻辑。

## 3. 策略 Schema v1（无 ask）

```yaml
# auto-run.policy.yaml —— run 的唯一治理来源
# 任何一节缺省 = 保守值；整文件缺省 = 内置「保守档」

on_decision:                  # 方向分歧（request_decision 提请）
  action: stop                # stop | continue
  principles: |               # 仅 action=continue 时注入（多行原则文本）
    - 优先推进已证伪链上最近的假设，不开新方向
    - 权衡取舍偏向可复现优于新颖

on_stall:                     # 空转：连续 N 轮无有效研究记录且阶段未推进
  tolerance: 3
  action: stop                # stop | continue（continue = 再给 N 轮宽限）

on_failure:                   # 同类工具 isError 连击
  streak: 3
  action: stop                # stop | continue

on_budget:                    # 预算耗尽
  action: stop                # stop | renew
  renew_limits: []            # action=renew 时：每次续命上限序列，序列耗尽后 stop

on_declare:                   # declare_completion 达成声明
  report: true                # 达成 → 自动 report/export 出报告 → completed（带 reportPath）
```

**铁律**：系统只产出证据与报告，不判 pass/fail——结论永远在人读报告时形成。

### 3.1 缺省档（CLI 不传 `--policy-file` 时）

全保守：`decision:stop, stall:stop, failure:stop, budget:stop, declare:report`。CLI 侧作为内置常量塞进 payload，走与自定义文件同一条校验链。

### 3.2 校验规则（启动即校验，失败拒绝启动）

- `action` 按节枚举（decision: stop|continue；stall/failure: stop|continue；budget: stop|renew）；
- `tolerance ≥ 1`、`streak ≥ 1`；
- `renew_limits` 数组长度 = 续命次数（renew 语义：逐次取序列值）；为空且 action=renew → 非法；
- `principles` 仅在 `on_decision.action=continue` 时有意义，其他情况忽略（不报错）；
- 未知顶层键 → 拒绝（防拼写错误静默降级为保守档）。

## 4. 记录增量

`AutoRunRecord` 增加：

- `policy`：解析后的策略对象（原样落盘，重启/僵尸结算读它）；
- `reportDir`：`on_declare.report=true` 时 report/export 产出路径（复用 1.4.1 既有字段，不新造名字）。

`policy == null` 的 run = **交互模式**（GUI 原生路径，行为与现状完全一致）。

## 5. Runner 改造点（loop/auto-run.ts）

`runAutoRunLoop` 各暂停点按 `record.policy` 分支，无 policy 走现有交互路径（一行不改）：

| 暂停点 | policy 分支 | 交互路径（无 policy，现状） |
|---|---|---|
| provider-error（invoke 报错） | 保守停止（不提请，无人应答=白等） | 现 raisePauseDecision |
| decision（§3 等待段） | `continue` → principles 作为 user 消息注入 loop 线 + 本条提请标记 resolved（一次性处置，防每轮重注入），继续跑；`stop` → 走 stopped 收尾 | 现 waitForDecisionInjection |
| stall | 触发判定沿用现有双信号（阈值换 policy.tolerance）；`stop` → stopped 收尾；`continue` → 清 streak 继续 | 现 raisePauseDecision |
| repeated-failures | 同上（阈值换 policy.streak） | 现 raisePauseDecision |
| budget | `stop` → stopped 收尾；`renew` → 按 renew_limits 序列自动改写 limit（复用续命语义），序列耗尽 → stopped | 现 wait(limit 变化) |
| declare | `report:true` → 自动 report/export → `completed` + reportDir；`report:false` → `completed`；**不建 verdictPackage**（无审可答，防 list 归一化出幽灵 verdict），declaration 留史 | 现 awaiting-verdict |

- `on_declare` 出报告失败（report/export 报错）→ 不阻断 completed，日志告警，list 可见记录；
- 开局快照 / checkpoint 快照保留现状（与 policy 无关）；
- 策略 stop 的收尾统一：persist + `auto-run:completed{outcome:stopped}` + 注回交互线（finishStoppedByPolicy）。

## 6. 同 envKey 互斥闸

`startAutoRun` 现有单实例闸（auto-run.ts:1734-1739）扩展为 workspace **或** envKey 命中即拒：

- 活跃态口径不变：running / paused / awaiting-verdict 全算占用；
- 错误文案分叉：同 workspace → 现有文案；同 envKey → 「环境 X 已被运行中的 auto run Y 占用，先 Esc 终止再启动」；
- 不拦战役（人工触发，人自管）；环境登记侧不加占用态。

## 7. 僵尸愈合

**现状已实现**（1.6.0 修复③，本版不改逻辑）：`recoverOrphanedAutoRuns` 在 sidecar 启动时把盘上 `running/paused` 记录统一落 `stopped`（pauseReason=sidecar-restart），`awaiting-verdict` 保留孤儿终审通道。策略 run 的终态同样被此路径覆盖（策略 run 的终态只有 running/completed/stopped，无 paused/awaiting-verdict）。

本版唯一增量：策略对象随记录落盘后，僵尸结算可读 `record.policy` 判断处置理由（现为统一「sidecar-restart」，语义不变）。

## 8. CLI 入口

- `buildRequestBody` 新增 `auto-run` 分支：
  - `start`：`{name, goal, envKey, criteria[], budget:{kind,limit}, policy, workspace}`；`--policy-file <path>`（1MB 上限，复用 readTextFileFlag 纪律）；无文件 → 内置保守档；`--budget-kind turns|tokens|time` + `--budget-limit N`；
  - `stop` / `budget`：`{id}`（`--id` 或 positional）；
  - `verdict`：`{id, verdict, note}`，verdict 枚举 CLI 侧校验（pass|fail|continue）——仅服务 GUI 交互 run 的补审，保留；
  - `list` / `clear`：`{workspace?, id?}`；`list` 人类可读输出待审 run 的 statement + criteria 预检（json 模式原样）；
- `cli-args.ts` 可重复旗标清单加 `criteria`；
- `HELP_TEXTS` 加 auto-run 组文案；`TOP_HELP` 组清单加一行。

## 9. GUI 边界（不改）

- AutoRunCard 不传 policy（payload 无 policy 键 → 交互模式）；
- 弹窗 / SSE 事件族 / verdict 终审弹窗全部现状；
- 重启后 GUI run 的 awaiting-verdict 孤儿终审通道保留（1.4.6 语义）。

## 10. 测试计划

- **策略解析/校验单测**：合法矩阵 + 非法矩阵（未知键/坏枚举/tolerance=0/renew_limits 长度错配）；
- **runner 分支单测**（auto-run.unit.test.ts）：decision continue 注入 / stop；stall tolerance 宽限；budget renew 序列耗尽；declare report → completed+reportPath；无 policy 走交互路径不变；
- **envKey 互斥**：同 envKey 拒 / 异 envKey 放行 / 同 workspace 旧文案；
- **僵尸愈合**：paused/running 落 stopped；awaiting-verdict 保留；
- **CLI**：buildRequestBody auto-run 分支、criteria 可重复、--policy-file 读取；
- **契约测试**：start 带 policy → declare → completed + reportPath 全链。

## 11. 验收标准

1. `zhishi auto-run start --policy-file x.yaml` 一条命令拉起，无人值守跑完出报告（completed + reportPath）；
2. 缺省档跑通（不传文件）；
3. 同 envKey 双开被拒、异 envKey 并行放行；
4. sidecar 重启后僵尸记录被按策略结算，无永久停滞；
5. GUI 交互路径回归零变化（全量测试绿）。
