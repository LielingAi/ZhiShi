## #2 `/env` 重新选择环境卡死

### 根因

`gateBusy` 守卫断链：

- 置位：Enter 提交前 `gateBusy = true`（`src/cli/tui/v2/app.ts:279`）。
- 复位：**仅** commit 失败的 catch 分支（`app.ts:295`）；成功路径（`app.ts:288-289`）与手动接入口径（`app.ts:346/363/380`）均不复位。
- `enterGate()`（`app.ts:192-202`）重置 mode/overlay/cursor，唯独不重置 `gateBusy`。

死锁路径：启动正门选定成功 → `gateBusy` 永久为 `true` → `/env` 重进 gate 后所有键在 `app.ts:253` 被吞（上下/Enter/Esc 全无效）。首次不卡是因为构造器初值 `false`；`--env` 跳过正门的用户不触发。

### 修复

1. `enterGate()` 入口重置 `gateBusy = false`（一行，覆盖所有进入路径）。
2. 附带修复：重进 gate 按 Esc 当前直接退出整个 TUI（`app.ts:264-268`，原为启动场景设计）。给 gate 记来源标记（startup / reentry），reentry 时 Esc 走 `enterChat()` 返回聊天。

## #3 滚轮翻历史（重新立项）

### 现状（原缺陷单已过时）

- 鼠标捕获 2026-08-17 已整体移除：`terminal-writer.ts:226-229` 注释（SGR mouse 禁用终端原生文本选择，回看待 PgUp/PgDn）；全仓无 `?1000h/?1002h/?1003h/?1006h`。
- `app.ts:614-618` 的 wheel 分支是死代码：`keymap.ts:130-134` 把所有 SGR mouse 序列吞成空键。
- 当前 HEAD 上滚轮无任何行为。原缺陷单描述的是移除捕获前的旧行为（当时根因：handler 无条件 `scrollBy`，缺状态门控）。

### 修复方案

受控重新引入 wheel-only 捕获：

1. 终端层：只开 wheel 报告（`?1006h` + 不带 motion 的捕获），不开点击/拖拽——保住终端原生文本选择，不重踩 2026-08-17 的坑。
2. `keymap.ts` SGR mouse 分支：只放行 wheel 码 64/65 产出 `wheel-up`/`wheel-down`，继续吞点击/拖拽。
3. 交互语义（已定案，方案 A）：任意态滚轮上滚 = 进入回看并翻历史（`scrollBy` 后 `following===false` 自然进入回看态）；Esc 或滚到底回最新（现有链路 `app.ts:597-600`、`viewport.ts:81-86` 已具备）。

## #4 会话按环境分线（映射结构 A1）

### 技术前提（已核实，全部成立）

- server 与引擎同进程，admin-api 已 import chat-engine（`admin-api.ts:110`），无循环依赖、无 RPC。
- busy 状态现成（`chat-engine.ts:160-161`）；「busy 拒绝」有先例（rewind/fork，`:1011/1044`）。
- 切会话肌肉现成：`switchPiSession`（`:874-889`，状态重置清单完整）。
- 原子写文件惯例现成：`withFileLock` + tmp+rename（`src/server/utils/file-lock.ts`）。

### 方案主干

- 独立映射文件 `~/.zhishi/env-sessions.json`：workspace × 环境键 → loopSessionId。IO 走 `withFileLock`（**不**照 `selection.ts` 的裸读写）。
- `environment/select`（`admin-api.ts:7115-7147`）落盘后联动引擎切线；turn 运行中拒绝，提示先 Esc 中断（handler 需改 async，路由处补 await，`index.ts:2485`）。

### 已确认决策（5 条）

1. **启动恢复 env-aware**：`restorePiSession`（`chat-engine.ts:281`）与 TUI 侧 `ensureAgentSession`（`entry.ts:49-78`）双处改造——按「工作区 + 当前选定环境」接线，无映射则开新线；废除「按全 workspace 最新 meta 接线」的旧语义（与分线冲突，且 gate 选定发生在 `ensureAgentSession` 之后，`entry.ts:96-103`）。
2. **reset 一致性**：`resetPiChat`（`:973-1003`）同步清对应映射——否则 reset 后按映射恢复会复活旧历史（`:971-972` 注释记载过同类活体事故）。
3. **映射键**：env 按 envId；recipe 按 instanceId；host 单独一条线（selection 三种 kind 见 `selection.ts:39-42`）。
4. **workspace 键规范化**：resolve + 统一斜杠后作键（斜杠漂移是活体坑，见 `chat-engine.ts:219-226`）。
5. **cron**：跟随当前选定环境的线，不单独特殊处理。

### 顺带处理

- 环境删除（`handleEnvironmentRm`，`admin-api.ts:6435`）时顺手清映射残留。
- 联动切线后 TUI 重拉回放：正门与 `/env` 重进均走 `enterChat()` repaint+pump（`app.ts:391-401`），已覆盖；但依赖 #2 先修好。
