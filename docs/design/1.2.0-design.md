# 1.2.0 设计：研究交付——/export 一键出报告

> 2026-08-21 立项。功能里程碑：留痕设施变现为可交付成果。
> 设计决策（已与用户敲定）：报告=目录（report.md + evidence/）；默认完整
> 导出、脱敏是显式选择（脱敏版不是成果报告）；TUI 单入口（脱离 TUI =
> 脱离环境）；报告生成走独立一次性 loop，不占引擎单例会话线。

## 架构分工

- **sidecar 服务端**（厚）：数据组装、证据回收、LLM 填肉、落盘。新模块
  `src/server/report/`。
- **TUI**（薄）：`/export` 斜杠命令触发 → 进度插行 → 越界批准模态（复用
  boundary-ask 通道）→ 完成行（报告路径）。
- CLI 入口本版不做（环境绑定只在会话在场时是热的）。

## 数据源（全部现成）

- 会话主线：`loop-sessions/<id>.jsonl`（1.1.10 `transcript.ts` 可读）
- 结构化事件：`research_events`（memory.db，task_kind/outcome/bug_class/
  summary/trajectory_ref）
- 子代理工作史：`/api/loop-session/messages`（1.1.10 建）

## 报告结构

```
output/reports/<YYYYMMDD-HHmm>-<envId>/
  report.md        # 按域模板：目标/方法/发现/证据/复现步骤/修复建议
  evidence/        # PoC、样本、截图（环境回收的文件本体）
  meta.json        # 生成时间/环境/模型/事件 id 清单/降级标注
```

按域模板：pentest（目标/侦察/发现/利用链/复现/修复建议）、whitebox
（输入面/确认漏洞/证据带 文件:行号/修复建议）、binary（目标/崩溃分析/
利用路径/证据）。无域信息 → 通用模板。

## 组装：确定性骨架 + LLM 填肉

1. 代码组装事实骨架：时间线（research_events 序）、每事件的 summary/
   bug_class/证据引用、关键 transcript 段（工具调用+输出原文）。
   **事实层不许 LLM 碰**——防幻觉的架构红线。
2. LLM 只写「过程叙述」段落（把骨架的每节写顺），独立一次性
   `runLoop`（无环境工具，独立 sessionId，不碰引擎单例状态/会话线；
   模型取工作区当前配置）。
3. 输入超长：骨架超 token 预算时按节截断 transcript 引用（保留事件层，
   砍原始输出），meta.json 记录截断。

## 证据回收链（本版的核心新机制）

1. **留痕纪律升级**：`research_log` 的 `trajectory_ref` 字段早已存在
   （store.ts:272）但没有任何 skill 引导填写——tool description +
   pentest/whitebox/ai-security/binary-exploit 等 skills 补纪律：
   「产出工件（PoC/样本/截图）必挂环境内路径」。
2. **导出按单回收**：收集当前会话相关事件的 trajectory_ref 清单 →
   经 extract 通道（`handleEnvironmentExtract`，scp → output/）批量
   回收到 evidence/。
3. **技术边（已核实现状）**：
   - extract 现为**单文件逐次越界问**（admin-api.ts:6356
     requestBoundaryAsk per call）——导出必须改成**批量一次批准**：
     把「落点 + 全部 N 个证据文件」一次列清，人批一次全收，拒则整批
     降级。实现：导出流程自己发一次 requestBoundaryAsk（对象清单完整），
     批准后内部回收不再逐次问。
   - extract 走 scp（ssh/vm 环境）；docker 环境无 scp 目标——本版
     docker 环境的证据回收直接走降级标注（如实写「docker 环境回收
     未支持」），不为它发明 docker cp 通道。
   - 环境已下线/不可达：回收失败 → 报告保留环境内路径 + 降级标注；
     transcript 内嵌证据（命令输出/PoC 全文常在工具结果里）作兜底引用。

## 导出闸门

- **一次批准**：`/export` 触发后先组装清单（落点 + 证据文件 N 个 +
  敏感项计数），一次 boundary-ask（host-write）列清，批准才动手。
- **敏感项清单**：复用 output-guard 的敏感材料检测扫骨架文本，
  命中计数（flag/密钥/IP 类）列进批准模态——知情在人，不替人删。
- **默认完整导出**；`--sanitize`（TUI 里 `/export sanitize`）才出脱敏版
  （命中项遮蔽为 `[redacted:类别]`）。

## TUI 侧

- `/export` 注册进 commands.ts；进度走 divider 插行（组装中/回收中/
  写报告中/完成）；批准模态复用 chat:boundary-ask 红模态（extract 已
  验证 HTTP pending 模式）；完成行给报告目录路径。
- 导出不阻塞会话：组装在服务端异步跑，turn 状态不受 export 影响
  （export 自己不是 turn）。

## 验收

用 1.1.8 三域真实 dogfood 数据各出一份：
- pentest 报告含完整利用链（SQLi→secrets→LFI→flag）且 evidence/ 有
  PoC 本体（需先在 pwn-vm 里补放工件并补登记 trajectory_ref——1.1.8
  跑的时候还没这个纪律）；
- whitebox 报告带 文件:行号；
- 环境下线场景演一遍降级标注。

## 边界（明确不做）

- CLI 导出入口；在线分享/协作；docker 环境证据回收；历史老会话的
  trajectory_ref 补登记（老数据无 ref 就按降级处理）。
