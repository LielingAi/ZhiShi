# 战役原语（discovery campaign）设计稿 —— 1.6.8

> 状态：设计稿 v1（2026-09-09）。实证输入：两轮轨迹分析（1.6.7 #4）+
> fuzz dogfood 实验（`docs/design/experiment-fuzz-dogfood.md`）。
> 纪律：本稿评审通过前不写实现代码；每条设计决策标注证据来源。

## 0. 一句话

**挖掘不是更长的任务，是战役（campaign）**：目标钉下后，搜索基座（盲跑）
持续运转，信号（覆盖率平台期/新崩溃/指纹分布）驱动 agent 在关键点介入，
引导回路（读源码 → 假设 → 定向构造 → 回灌）负责突破盲跑到不了的深度——
墙钟预算按天计，产出按崩溃类收口。

## 1. 证据回顾（为什么是它）

1. **挖掘从未启动**（轨迹 25 事件/17 会话零 fuzz）：可发现性断线已由 1.6.7
   R1/R2 接线，但接线只解决「能跑」，不解决「跑成搜索」；
2. **盲跑 121k execs 零崩溃 vs 引导秒级命中**（dogfood §4）：盲变异在结构
   语义类 bug（转义计数 vs 声明上限）面前命中概率指数级低——**挖掘的第一
   变量是引导不是算力**；
3. **复现的成功结构**（轨迹 Q1）：锚点 + 受控变体收敛 + 显式假设证伪
   （H/V/C/R 档案真实驱动行为）——战役设计复用这套已被实证的内核，把
   「锚点」从「补丁/CVE」换成「盲跑信号 + 源码阅读」；
4. **agent 挖掘能力被反证**（mts9dvha x1→x50 打出 root）：设计目标是给
   这个能力一个**过程容器**，不是教模型新技能；
5. **时间尺度错配**（轨迹 Q4）：瓶颈是墙钟（构建等待/环境稳定/用户离场），
   不是上下文预算（峰值 41.5%）——战役预算是墙钟制的。

## 2. 概念定义与现有件的关系（不新造轮子）

| 件 | 在战役里的角色 | 关系 |
|---|---|---|
| auto loop | 战役的 **agent 介入回合**载体 | 并列不嵌套：auto loop 是目标驱动循环（轮次/费用预算）；战役是信号驱动编排，介入回合可以就是一次 invoke |
| env_bg | 搜索基座执行（afl 长跑等） | 复用；1.6.7 R2 的完成回注是信号通路的已落地地基 |
| research_archive | **假设账本**（H#/V#/C#/Q#） | 复用——战役的假设队列就是档案实体，不另造队列 |
| fuzz-runner / crash-triager | 介入回合的打法人格 / 分拣批处理 | 复用（delegate_task 委派只用于短任务，见 §5 约束） |
| research_log | 产出落库（task_kind=fuzz，1.6.7 R5 已分桶） | 复用 |

**delegate_task 的同步 await 语义与战役的异步介入冲突**（立项点名的核心
题）的解法：战役的介入回合**不嵌套委派长跑**——介入回合本身是环境内的
工作 loop（直接 env_exec/env_bg），需要批处理时委派**短**任务（崩溃分拣
这类有明确终止的），长跑只由战役本体经 env_bg 持有。

## 3. 战役状态机

```
created ──起跑──> running（基座盲跑中）
running ──平台期信号──> plateau（破冰回路介入：读源码→假设→定向构造）
plateau ──构造回灌──> running（语料/harness 更新后继续盲跑）
running ──新崩溃信号──> triaging（crash-triager 批处理分拣）
triaging ──去重出类──> running（变体回灌）或 deepening（crash-triager 深挖模式）
任意 ──墙钟/费用预算耗尽──> paused（人可续命，auto loop 同语义）
任意 ──人停/成功判据达成──> completed / stopped
```

- **破冰回路**（本设计的第一需求，dogfood §4 实证）：plateau 不是「停」，
  是引导回路的触发器——介入回合读目标源码 → 假设落档案（H#）→ 定向构造
  输入/变体 → 崩了转 triaging，没崩回灌语料转 running；
- **平台期判据**：fuzzer_stats 周期采样——`cycles_done ≥ 1` 且最近 N 分钟
  无新路径（saved paths 不涨）或 execs_per_sec 归零；N 与采样间隔是战役
  参数（缺省：采样 5min 间隔，连续 3 次无新路径 = 平台期）；
- **成功判据**：立项时钉死（如「≥1 类去重崩溃且 crash-triager 出结论」），
  与 auto loop 的验收条件锁定同纪律。

## 4. 信号源注册表（R2 的泛化）

战役把「bg 完成回注」泛化为**信号 → 介入点**的注册表：

- `bg:finished`（已落地，R2）——基座进程退出（含 crash）；
- `fuzz:plateau`（新）——采样器判定的平台期；
- `fuzz:new-crash`（新）——崩溃目录出现新 id:* 文件（轮询或 fs watch，
  按环境通道能力降级）；
- `budget:*`（复用 auto loop 语义，墙钟化）。

信号到达 → 若战役活跃且无进行中介入回合 → 开一个介入回合（invoke 通道，
headless），注入信号上下文 + 战役状态快照（档案实时状态段已有此机制，
1.4.4 的 renderArchiveForInjection 直接复用）。介入回合并发闸：同一战役
同时最多一个（与 auto loop 单实例闸同型）。

## 5. 预算与持久化

- **墙钟预算**（小时/天）+ 费用上限（复用 auto loop 的 tokens 语义）双闸；
  墙钟计时扣暂停（1.6.0 审计已修的 time 预算语义直接沿用）；
- 战役记录落 `~/.zhishi/campaigns/<id>.json`（状态机快照 + 信号史）；
  sidecar 重启愈合对照 auto-run 的既有愈合件（1.6.0 第三批）；
- 假设/证据不过战役记录——全部走 research_archive（H#/V#），战役记录只
  存状态机与信号，内容账本唯一事实源是档案（不双写）。

## 6. 产出与收口

- 每类去重崩溃 → crash-triager 批处理入口 → research_events（fuzz 桶）；
- 战役收口（completed/stopped/预算耗尽）→ 一条 fuzz 汇总事件（时长/execs/
  覆盖/崩溃类数）+ 轨迹索引；
- GUI：战役面板（状态机 + 信号时间线 + 预算条）——v1 最小面：状态 + 最近
  信号 + 停/续按钮，时间线留 1.6.9 再议。

## 7. 反例与砍单（先写死，防 scope 蔓延）

- **不造通用工作流引擎**——战役只服务发现式搜索（fuzz/变体/差分）；
  通用编排是 2.0 话题；
- **不造分布式 fuzz 集群**——单机单环境；多 VM 并行是 hypervisor 的事；
- **不做 LLM 变异器**——1.6.1 实证 LLM 增量是速度不是独占，战役里 LLM
  的角色是引导回路（读源码/假设/定向构造），不是逐样本变异；
- **不动 delegate_task 语义**——同步 await 保留（短任务正确形态），战役
  的异步介入走 invoke 通道不是嵌套委派；
- **环境聚合**（多配方合成一个环境）不在此版——1.6.7 边界已记录，dogfood
  未暴露它为瓶颈。

## 8. 验收实验（先于实现锁定判据）

复跑 1.6.7 的注入靶（cJSON 双注入 bug），战役形态下**零人工介入**：
- **成立**：盲跑基座 → 平台期信号触发破冰回路 → 至少命中 1 个注入 bug
  （escape_track 或 key_audit 族）→ crash-triager 出结论 → 事件落 fuzz 桶；
- **不成立**：破冰回路在盲跑 121k execs 同等预算内零命中——回炉（设计错
  而不标完成）；
- 对照：1.6.7 盲跑基线（121k execs / 0 崩溃）与本实验同靶同种子。
