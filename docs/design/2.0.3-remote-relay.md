# 2.0.3 设计：团队大脑内建中继（remote relay——把 ssh -L 做成应用能力）

> 2026-10 立项。动机一句话：**成员 GUI 直连团队大脑不该要求成员手工架 SSH 隧道**。
> 交付后：成员填地址 + token 即用（应用自起回环中继）；SSH 隧道降级为
> 旧版应用 / 浏览器 dev / 无 Rust 环境的备选路径。

## 背景与已核实事实（验收的锚）

1.8.7 团队大脑上线时，成员 GUI 的唯一可用传输是 `ssh -L 7411:127.0.0.1:7411`
手工隧道（用户指南 §10）。当时的陈述是「Tauri 客户端的 /api/*、/sessions/*、
/chat/stream 全部经 Rust local_http 代理转发（server→server，无 Origin 头），
webview 直连大脑的只有 /refs/ 大文件取回」——**本设计动工前复核，该陈述已
过时/不实**（`src/server/auth/cors.ts` 头注释所描述的架构不存在）：

- 实读 `src/gui/src/client/sse-client.ts`：`GuiSidecarClient` = webview 里裸
  `fetch`（fetchImpl 默认 `fetch.bind(globalThis)`），`/api/admin/*`、`/chat/*`、
  `/sessions`、`/refs/`、SSE（fetch-based reader）**全部** webview 直连
  `client.base`。GUI 侧没有任何 Rust HTTP 代理；`src-tauri/src/local_http.rs`
  只是 reqwest 构造器工具（no_proxy 纪律），不是代理服务器。
- 终端 WS（`src/gui/src/components/AttachView.tsx` + `client/term-client.ts`）
  也是 webview 原生 `new WebSocket(...)`，token 走 `?token=` query。
- 所以远端模式下 GUI 不是「只有 /refs/ 被拦」，而是**每个请求都被混合内容
  规则掐死**（安全上下文页面 → 非回环 http）；auth 开启后 CORS allowlist
  （`src/server/auth/cors.ts::isAllowedBrowserOrigin`）也只放行 Tauri origin
  与回环 origin——「让 GUI 页面自己也走 http://局域网IP 打开」同样被预检 403。
- 结论：不碰 HTTPS 时，唯一活路是让 **GUI 请求的目标保持回环**。
  `ssh -L` 只是实现回环目标的手段之一，不是本质。

## 方案

等价内建 `ssh -L`：成员机上由应用自起一个只绑回环的 TCP 转发器，
webview 全程连 `http://127.0.0.1:<relayPort>`，转发器哑管道到大脑。

```text
webview ──HTTP/SSE/WS──► 127.0.0.1:<relayPort> ──哑 TCP 管道──► 大脑:7411
```

选 TCP 管道而非 HTTP 反向代理的原因：管道不解析协议，HTTP / SSE 长连接 /
WebSocket upgrade / `/refs/` 大文件**零改动全透明**；没有 HTTP/WS 解析就没有
头改写、缓冲、upgrade 处理的整类 bug。

### 组件

| 件 | 位置 | 职责 |
|---|---|---|
| 转发器 | `src-tauri/resources/relay.cjs`（新，纯 `node:net`，CommonJS——仓根 `"type":"module"`，`.cjs` 是刻意的） | 监听 127.0.0.1:0，每连接双向 pipe 到 `--target-host/--target-port`；stdout 首行 `ZHISHI_RELAY_READY <port>`；不打印 payload/URL/token |
| 生命周期 | `src-tauri/src/remote_relay.rs`（新模块） | spawn/kill relay.cjs；状态机 Stopped/Starting/Running/Failed（Drop 自动收尸；epoch 防过期 reader 线程写回；失败冷却 5s 防轮询变 spawn 风暴） |
| IPC 契约 | `commands.rs::get_sidecar_port(remote_url)` | 远端模式返回**中继端口**（原返回 None）；本机模式逐字节不变。稳态 ensure = 锁内一次比较 |
| 前端 | `model/connection.ts::pollRemoteRelayPort` + `useGuiStore.init` 远端分支 | Tauri 环境轮询中继端口（500ms，20s 超时），client base 指向 `127.0.0.1:<port>`；浏览器 dev 无 Rust，维持直连（SSH/portproxy 备选） |
| 打包 | `tauri.conf.json` bundle.resources 增映射 | dev/打包同构（resource_dir 同源），构建脚本零改动 |

### 关键语义

- **半关闭**：`net.createServer({ allowHalfOpen: true })` + 双 pipe（end:true）。
  缺 allowHalfOpen 时 Node 会对「收到 FIN」自动回 FIN——中继抢答，半关闭尽毁
  （实测：目标端 `end` 事件后回包丢失）；换向关闭用 `destroySoon()` 而非裸
  `destroy()`——裸 destroy 会把已排队未 flush 的回包变成 RST（实测 ECONNRESET
  吞掉 WebSocket/SSE 的正常关闭握手）。两条都是 relay.cjs 端到端测试钉死的。
- **目标不可达**：upstream connect 报错 → 立即 destroy 该连接（RST），
  webview 拿到 connection refused 语义——探活/重试归上层连接失败态。
- **安全边界**：中继只绑回环；本机任何进程可借道——与 ssh -L 信任模型一致，
  大脑侧 token 鉴权兜底。relay 不解析字节，Bearer/`?token=` 不可见也不可见。
- **退出**：离开远端模式（IPC 传空）→ stop；`RunEvent::ExitRequested` → stop；
  目标 URL 解析失败 → stop（不让旧目标幽灵转发）。
- **服务端零改动**：CORS/鉴权/路由一行未动。

### 已知取舍

- **孤儿中继**：app 被硬杀（taskkill /F）时 relay.cjs 子进程可能残留——它是
  回环监听 + 无 token 不落盘，危害等价于一个没连的 ssh -L 壳子；重启应用进
  远端模式会重新 spawn（端口由 OS 分配，不冲突）。不做 pid 文件清理（v1 克制）。
- **浏览器 dev**：`npm run dev:gui` 的浏览器页拿不到 Tauri IPC，维持直连 +
  被拦的旧行为（dev 成员自架隧道/portproxy）。
- **Rust 侧本机不可编译验证**（CLAUDE.md 已知遗留：本机无工具链）——
  remote_relay.rs 只经自查 + CI `cargo test`/`clippy -D warnings` 把关；
  relay.cjs 与前端逻辑本机全绿（12 新测试 + 全量 unit 池 2874 绿）。
