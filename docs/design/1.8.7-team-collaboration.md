## 目标与非目标

**目标**：多名成员用各自的 ZhiShi 客户端（应用 / CLI）连接**服务器上唯一的
sidecar（团队大脑）**，共享研究档案、claims、知识库与现场；研究线分「共享线」
与「私有线」两种；环境（docker/vm）集中运行在服务器上。

**非目标**（刻意不做）：

- 多本体互联（federation）：一个大脑被用到顶之前不做，大概率永远不做。
- 共享 transcript：协作共享的是**结论、档案、认领、知识**，不是对话。
- 公网面：第一版只承诺内网 / SSH 隧道；token 是鉴权不是加密。
- 引擎多线化（真并发）：见 P3——它是唯一的大块头，**协作 1.0 不含它**。

## 已核实的架构事实（验收的锚）

- HTTP sidecar：`src/server/index.ts:494-512`，`honoServe` 硬编码绑
  `127.0.0.1`；admin 路由表 `routeAdminApi`（:227-387，POST `/api/admin/<route>`，
  100+ 条）；非 admin 路由（`/health`、`/chat/stream`、`/chat/send` 等）同端口；
  term 的 WS upgrade 挂同一 http.Server（:516）。**认证：完全没有**——现有安全
  边界就是「绑回环」（:654-656 注释明写）；CORS `ACAO:*`。
- GUI 与 sidecar 的关系：**GUI 不内嵌 server，就是 HTTP 客户端**（
  `src/gui/src/client/port.ts` / `sse-client.ts` 的 base URL 已有注入缝，浏览器
  dev 模式本来就这么连）；Rust（`src-tauri/src/sidecar.rs`）按 Tab spawn 本地
  sidecar 并写 `sidecar.port`。
- CLI 是零状态 HTTP 客户端：`zhishi.ts:1589` 硬编码 `http://127.0.0.1:<port>`；
  `sidecar-ensure.ts` 在本地无 sidecar 时**自作主张拉起一个**（远端模式必须关掉
  这个行为）。**远端连接概念今天不存在**（无 --server/--remote，ZHISHI_PORT 只
  给端口不给主机）。
- 研究线：会话落盘 `~/.zhishi/loop-sessions/*.jsonl`；分线映射
  `~/.zhishi/env-sessions.json`，键 = `workspace::envKey`；环境选定
  `~/.zhishi/env-selection.json`（per-workspace）。**"当前线"是引擎单例字段**：
  `chat-engine.ts` 的 `defaultEngine`（sessionId/messages/queue/busy/abort/
  currentEnvKey，:449-470）——一个 sidecar 同时只跑一条线、一个 busy 标志。
- 实时事件：**`GET /chat/stream` 的广播已经是 fan-out**（`sse.ts` 全局 clients
  集合 + 每客户端背压队列 + 15s 心跳 + last-value cache 重放）——但事件不分线
  不分人，多线并存时这是第一处要改的。
- 署名缝（已存在）：archive `CorrectionEntry { by: 'human'|'model' }`、expert
  的 `reviewer TEXT`（唯一真的人名字段）、trust `actor`（agent/user 二分）。
  **没有署名**：research_events、SessionClaim、ArchiveEntity。
- 环境：`environment/*` 的命令在环境内跑，但发起进程（docker CLI / ssh / vmrun）
  全部跑在 sidecar 所在机器——**环境在服务器上天然成立**；缺口是**没有文件
  上传/下载路由**（push/extract 的端点是 sidecar 本机路径）。
- 全局锁（多人会撞的）：引擎单例单 turn；auto-run 同 workspace+env 互斥；
  intel update 单飞；config/env-sessions/env-selection 全部 withFileLock
  （跨进程已串行，但锁粒度是整个文件）；boundary/decision 的 pending Map 全局，
  谁的客户端都能答——**"谁批的"今天没法回答**。

## 方案

### 拓扑

```
成员的 ZhiShi 客户端（应用 / CLI）── HTTP + Bearer token ──► 团队大脑
                                              （服务器上唯一的 sidecar）
                                              模型/loop/档案/知识/蒸馏/环境全在这
成员机器上只留：宿主 shell（env_exec 本地跑）、成员自己的工作区文件。
```

### 研究线双线制

| 模式 | 归属键（`env-sessions.json`） | 谁能写 | 谁能看 |
|---|---|---|---|
| **私有线**（默认） | `workspace::user::envKey` | 仅本人 | 仅本人 |
| **共享线** | `workspace::shared::envKey` | 任何「操作员」级成员 | 全体成员 |

共享线不是新造的东西——它就是「不带用户段的分线键」，现有 `workspace::envKey`
的分线语义原样继承，只是键空间加了一段「谁」。私有线是开线的默认；共享线显式
开（新路由 `line/share {loopSessionId}` 或开线时指定）。共享线上所有人的实体、
claims、纠正、推进**都署名**（P2）。

### 角色三档（随 token 下发）

- **只读**：看档案/claims/进度/知识（含 SSE 订阅）。
- **操作员**：+ 环境生命周期（up/down）、实体推进（resolve）、认领（claim）。
- **审定人**：+ 纠正（correct）、专家审定（promote/review）、审批 boundary ask。

### 阶段（每步独立交付价值）

| 阶段 | 内容 | 复杂度 | 风险 |
|---|---|---|---|
| **P0.5** 客户端远端模式 | CLI `--server`/`--token`（远端不 spawn 本地 sidecar）；GUI 加「本机/团队大脑」开关（Rust 不 spawn，base URL + token 注入） | 低（~百行+测试） | 低 |
| **P1** 大脑可达 + 鉴权 | 绑址参数化（默认仍 127.0.0.1）；`handleRequest` 外层一处 auth 中间件；token+角色存 config.json `auth` 键；CORS 收紧（先验证 GUI 的 origin） | 低-中 | 中 |
| **P2** 身份贯穿 | 署名灌进五个缝：`CorrectionEntry.by`、`reviewer`、`actor`、`SessionClaim.owner`、`research_events` 加 `by` 列（ALTER 迁移）；boundary/decision 加归属与应答者记录 | 中 | 低-中 |
| **P3** 引擎多线化（2.0） | 引擎单例 → 引擎实例表；busy/队列/pending 全 per-line；SSE 按线分流；**协作 1.0 不含它** | 高 | 高 |
| **P4** 文件传输 | 上传/下载路由（multipart/stream；复用 `/refs/` spill 模式）；boundary 集成（写宿主 ask） | 中 | 中 |
| **P5** 环境集中 + 占用 | `environment/engines` 服务器探测一次即共享；环境占用位（哪条线/谁在用）投影进 list | 低-中 | 低 |

### 协作 1.0 的边界（明确告诉成员）

1.0 里**成立**：同一份知识/档案/claims、所有记录署名、共享线与私有线、环境
在服务器上、占用可见、文件上传下载、远端客户端。
1.0 里**不成立**：两个人同时在两条线上跑 turn——引擎单例，一条线一次一个
turn（busy 闸现成语义；多出的 send 进 steering 队列，换线走 `/sessions/switch`）。
对小团队这条限制大概率长期不痛；P3 只等它真撞疼了再上。

### P3 的拆法（等它来的那天）

1. 引擎注册表，但只装一台（机械重构，行为不变；现有单测当护栏）。
2. 所有路由与 SSE 按线寻址（sessionId 参数，缺省 = 当前线，兼容旧客户端）。
3. 放掉一台上限 + 空闲回收（transcript 在盘上，回收不丢历史）。

## 风险分级

### R1 致命：把零鉴权服务开出回环

该 API 能 `docker exec`、`docker cp`、改配置——鉴权没做全就监听外网，等于
给局域网发一把 root。**P1 是加固工程，不是加个 Bearer**：

- 100+ 路由按角色**逐条分类**（开健康检查、只读、操作员、审定人）。
- **查 `config/get` 是否回传 `providerApiKeys`**——若吐明文 key，必须补
  redaction 或限制为审定人可读（这条是动工第一天就要核的事实）。
- term 的 WS upgrade 单独过闸（不在 HTTP auth 路径里，全案最容易漏的一针）。
- CORS 收紧前先实机验证 GUI 的 origin 形态（Tauri origin 不对会把自家 GUI
  锁在外面）。
- 传输：token 只鉴权不加密，内网裸跑可被嗅探——第一版 **SSH 隧道 / WireGuard**，
  本体不碰 TLS。

### R2 高：P3 的回归面（协作 1.0 不做它，此处仅备案）

`defaultEngine` 是渗透式假设；GUI/CLI/auto-run/campaign/cron/boundary/queue
全在面上。按上面三步拆；护栏就是现有测试（chat-engine.unit、
admin-environment-select、sse-whitelist-crosscheck、auto-run 几套）。引擎 ×N
的内存与事件风暴要实测；空闲回收是刚需。共享线并发写档案要过落盘纪律
（per-line + 文件锁，照 memory.db/config 惯例）。

### R3 高：数据迁移

- `research_events` 加 `by` 列：**迁移前强制备份 `~/.zhishi` 整目录**，
  迁移后核对行数与关键记录（store.ts 有 ALTER 迁移惯例 345-373）。
- `env-sessions.json` 键格式变更必须做**旧键回读**，否则现有 22 条线的映射
  全断——表现为「线还在盘上，但选现场后不接回那条线」。

### R4 中：多人下边界/审批语义漂移

D14/D17 按「一个可信的人」设计：ask 要有归属（谁问、谁批——审定人角色）；
`envSwitchBlocker` 这类 busy 闸，共享线上要从「全局一个 busy」变成「该线的
busy」（P3 审计点）。

### R5 中：远端模式下客户端的「本地路径残留」

CLI/GUI 里凡是**绕过 HTTP 直接读 `~/.zhishi`** 的路径，远端模式下都会读到
本机那份错的——P0.5 必须含一轮 CLI 子命令审计（`expert new/edit` 的编辑器
往返是本地行为、OK；凡是读文件拿配置的，确认它走 admin API 而不是读盘）。
GUI 的 Rust 侧现在每 Tab spawn 一个本地 sidecar，远端模式必须**彻底关死**，
否则出现「连着远端却在本地起了一个没人用的」。

### R6 低：升级兼容

团队里服务端与客户端要同版本；客户端打到没有的路由按「不可用」降级（照抄
桥接层已有的降级纪律）。

## 兼容性原则（保住现有版本的唯一办法）

**所有新行为 opt-in**：绑址默认 `127.0.0.1`；auth 只在配了 token 时启用；
远端模式显式开关；引擎在 P3 前维持单例。**本地单用户路径一字节不变**——
四种默认状态下与 1.8.6 的行为对照即验收。

## 验收门槛（go/no-go）

- **P0.5**：本地模式一字节不变（默认不加 `--server` 时行为对照）；远端模式下
  CLI 不拉起本地 sidecar（进程表可证）；CLI 子命令读盘审计清单全部走完。
- **P1**：路由角色分类表全量过一遍 + config/get 的 key redaction 已核 +
  WS 闸 + CORS 实机验证 GUI 仍通——**四条不齐，不绑任何非回环地址**。
- **P2**：memory.db 迁移前备份 + 迁移后行数核对；署名在档案实体/claims/
  留痕/审定四处可见；boundary 应答记录到人。
- **P4**：上传/下载带角色检查 + boundary（写宿主 ask）；大文件走 spill。
- **每阶段**：现有测试全绿（单引擎状态下）+ 本地单用户行为对照无差异。

## 回滚策略

新行为全部可被四个默认值关闭；数据迁移前先备份后动，失败回滚备份；
P3 的三步拆法保证每一步独立可回滚（第一步是纯机械重构）。

## 开放问题（动工前最后一个点名的）——**已收口（2026-09-29）**

1. 共享线的开启方式：`line/share {loopSessionId}` 显式共享一条已存在的私有线（已按此落地，owner 或 reviewer 可转）。
2. 角色三档（只读 / 操作员 / 审定人）——已按此落地，够用。
3. 传输第一版：**SSH 隧道（已定案）**——而且是实证定案，不是偏好：
   **混合内容拦截**。GUI 的 Tauri webview 在 Windows 上以
   `http://tauri.localhost` 为 origin（Chrome 视 `*.localhost` 为安全
   上下文），安全上下文不得再请求**非回环**的 `http://` 地址——成员 GUI
   直接填 `http://<服务器IP>` 会被浏览器在请求发出前拦截
   （`TypeError: Failed to fetch`，2026-09-29 实测；回环地址豁免，这就是
   本机 `http://127.0.0.1` 一直没事的原因）。于是「成员直连 IP」在 Tauri
   webview 下根本不成立，可用路径只有三条：**SSH 隧道**（
   `ssh -L 7411:127.0.0.1:7411 user@server`，成员连自己的 127.0.0.1）、
   **HTTPS**（自签 + 成员手动信任 / 正经证书）、**本机回环**。第一版 =
   隧道；CLI 用户不受此限（无浏览器层，`zhishi --server http://<IP>`
   直接通）。HTTPS 列为后续选项，不在 1.8.x 范围。

## 1.8.8 补丁：模式角标（WREN 提出）

「我当前是团队模式还是单机模式，必须在界面上有明确表示，不然使用者会
忘记自己在哪个大脑上操作」——StatusBar 加常驻角标：`本机`（dim）/
`团队大脑 · <host>`（cyan）/ `团队大脑 · 连接失败`（amber，tooltip 给
错误）/ 连接中；点击直达设置 → 连接页（store 新增 `settingsTab` +
`openSettingsTab`）。随 1.8.8 发布（晚于 1.8.7 构建，故 1.8.7 安装包无）。
