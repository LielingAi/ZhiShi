# auto loop agent 设计底账

> 版本：2026-08-26 定稿（讨论收敛，用户拍板）。状态：设计定稿，未立项——立项后细节（参数 dogfood 调参、事件族命名、验收包 UI）随版本落地。
> 定位：研究员给目标，agent 自主跑完整研究周期（侦察→分析→构造→执行→评估），多 turn 连续推进；人在暂停点介入，不在每轮介入。

## 1. 定调：目标式 + 研究阶段进度锚

- **目标式**（用户拍板）：任务式已有承载（Task Center / `delegate_task`），auto loop 不做清单执行；研究是目标驱动、路径探索式的，auto loop 服务「配合研究员做更好的研究」。
- **进度锚 = 研究阶段**（1.2.7 阶段框架的第二个用途）：锚定/侦察/分析/构造/执行/评估——阶段推进是进展，阶段停留且无证据是空转。一个框架两个用途：上下文压缩锚定（已有）+ auto loop 进度状态机（本设计）。
- **不另起炉灶**：auto loop = 现有 turn 循环上加一个目标层（目标 + 预算 + 暂停点 + 进度回报）。

## 2. 核心原则

1. **判定权在 harness，陈述权在模型**——模型不能既当运动员又当裁判（「做完了」会幻觉、「卡住了」不自知、「不会」还自信）。harness 用证据判定（研究记录增量、阶段推进、工具失败率、预算），模型在判定触发时输出陈述。延续「规则即数据」哲学（boundary 入向 deny + output-guard 出向净化）。
2. **验收条件人定且不可变**——研究员在启动表单定义，精确、可验证；启动即锁定，agent 不能改、不能自我降级（把「拿 flag」漂移成「找到方向」再宣布完成）。人可 Esc 终止、决策点响应、废弃重建；改条件 = 废弃重建。
3. **运行中只能观察**——不可切换环境、不可输入内容（steering 关闭）、环境锁定（在哪个环境就是哪个环境）。人只能：观察进度 + 暂停点响应 + Esc 终止。**与控制四要素的对照（2026-08-26 对齐记录）**：「插得进」在 auto 模式 = 检查点介入 + Esc 终止（暂停点即插入点），非「随时输入纠偏」；普通会话的随时纠偏能力不受影响——这是 auto 模式的形态选择，不是能力退化。
4. **安全网优先级高于循环效率**——越界/分歧/空转/反复失败/预算耗尽是硬暂停，循环本身只是软推进。
5. **「研究阶段」两用途口径对齐（2026-08-26 实施注意）**：1.2.7 阶段切分服务于上下文压缩（内容信号切分），auto loop 的进度状态机服务于进展判定（证据/行为）——同一词两个用途，实施必须复用同一阶段分类器，避免两套判定漂移；空转检测以「新增有效研究记录」为主信号、阶段推进为辅信号。

## 3. 启动表单（字段定义）

| 字段 | 语义 | 约束 |
|---|---|---|
| 任务名 | 一句话摘要（列表/回报卡标识） | 必填 |
| 环境 | loop 绑定的环境（单环境深潜） | 必填，启动即锁定，运行中不可换 |
| 目标 | 要达成什么的陈述（驱动循环的锚） | 必填 |
| 预算 | **三选一**：轮次上限 / token 上限 / 时间上限 | 必填一档，默认保守（如 50 轮 / 8M tokens / 2 小时） |
| 验收条件 | **自由文本多条**（「+ 添加条件」），每条一条可验证陈述（如「输出 flag{…}」「PoC 连续 3 次稳定复现」） | 必填 ≥1 条；启动即锁定 |
| 开局快照 | 启动前自动快照（干净现场，失败可回滚） | 默认开 |
| 完成报告 | 达成后自动出报告（/export 同链路） | 默认开 |

（范围边界后置——1.0 不做。）

## 4. 运行期交互模型（状态机）

```
启动（表单提交）→ 开局快照 → 运行（观察态）
  → 暂停点（决策面板响应）→ 继续 / 终止
  → 达成 → 验收包 → 人终审 → 完成 + 报告
  → Esc（运行中任意时刻）→ 终止 loop，会话保留回普通模式
```

- 运行态：输入区禁用、环境切换禁用、steering 通道关闭（与普通会话「运行中输入即纠偏」显式区分）。
- 暂停点响应：复用决策面板（1.3.2 `request_decision` 机制原样接上）。
- **Esc = 终止**（用户拍板）：不做「暂停挂起」第三态——现场在环境快照 + task.md，重新发起成本低。
- 预算耗尽：checkpoint（落 task.md + 快照）→ 提请续命（人决定加不加，agent 无权自己加）。

## 5. 暂停点全景（两层互补）

**模型主动（已有）**：
- 越界 → boundary-ask 硬批（四类跨界动作逐次问人，无「永远允许」；auto 模式下此纪律不漂移）
- 方向分歧/无把握 → request_decision（先查 expert_search，命中可验证则不问）

**harness 被动（新增，证据源全已存在）**：
- 空转检测：连续 **6** 轮无新增有效研究记录（wrong/无效不算）且阶段未推进 → 提请（附最近动作摘要）。默认值 dogfood 后调参。
- 反复失败：同类工具连续 **3** 次 isError → 提请（模型说「有把握」但证据说「反复失败」，harness 有权不信）。
- 预算耗尽：checkpoint + 提请续命。

**阶段边界（不暂停）**：阶段推进 → 拍肩膀回报结论（侦察完了发现 X，进分析）——过程静默、结论插行。

## 6. 达成与验收（对称于「人定义验收」）

- 验收条件人定 → **达成人终审**：agent 宣称达成 → harness 提交验收包 → 人确认才算完成。
- **验收包证据结构**：每条验收条件 → 状态（有证据/无证据）+ 研究记录引用（E#N 口径，同决策块 expertRefs 风格）+ 模型陈述（哪条证据支撑哪条条件）。
- 人终审界面：条件列表 + 证据 + 三按钮「通过 / 不通过 / 继续跑」。harness 只做证据预检，终审权在人。

## 7. 工程形态

- **复用 invoke 通道**（cron headless 线语义，1.2.6 B2 已建）：auto loop 在独立 loop 线跑，不污染主会话；完成后线可回看（loop-sessions 持久化已有）。
- **auto-run runner**（服务端新模块）：表单落盘（auto-run 记录，可追溯）→ 循环 = 每轮结束自动发起下一轮（不等人消息）→ 暂停点挂起等响应 → 达成/终止收尾。
- **SSE 事件族（新增）**：`auto-run:started / phase-changed / turn-completed / paused / budget-warning / completed / verdict-requested` 等——进注册表 + crosscheck 双向对账（1.3.10 纪律）。
- 空转/反复失败的证据判定复用：research_log（增量）、1.2.7 阶段切分（推进/停留）、工具结果（exit code / isError）、turns/tokens 计数。

## 8. GUI 观察界面

- 启动表单模态（决策面板同族样式）
- 运行中卡片：阶段指示、轮次计数、预算余量、最近结论行（拍肩膀）、Esc 提示
- 暂停点：决策面板（已有）弹出
- 验收包模态（人终审）

## 9. 风险与边界

- **token 成本**：预算必填兜底；token 档默认保守。
- **「有进展但方向错」**：空转检测兜不住——由人观察 + Esc 终止兜底（「只能观察」模式的价值所在）。
- **自由文本验收条件的可判定性**：人终审兜底。
- **与 /bg 转后台的关系（2026-08-26 决策：砍掉）**：/bg 转后台自 1.3.2 起单独立版挂账，auto loop agent 立项后其价值被全覆盖——长跑研究走 auto loop（前台可观察、有暂停点、有验收），环境内长驻进程走 env_bg（真相在环境内）。/bg 是纯重复形态，砍掉，不再挂账。
