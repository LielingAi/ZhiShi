# 实验：崩溃变体深挖——LLM 变体生成 vs 愚蠢回灌（1.6.1）

> 状态：**标准已锁定（2026-09-03，先于实验提交入库）**。判定标准（§4）跑后不改；实验结论跑出后补在 §6。
> 缘起：借鉴 colony / Fuzzillai 评估中，「崩溃变体深挖闭环」（crash → 根因 → 变体 → 验证 → 回灌）被列为 1.7.0 候选。但反证发现三条软肋：①zhishi 真实使用数据里 fuzz 断链从未实际造成损失；②Fuzzillai 的同类闭环（EBG-Crash）机制走通但新 bug = 0，是最接近的对照实验且结果为负；③存在零 LLM 成本基线（afl-tmin + 回灌），LLM 增量从未被测量。故先实验后立项：**本实验裁决「LLM 变体深挖相对愚蠢回灌有无增量」，通过才进 1.7.0**。

## 1. 实验问题

> 给定一个崩溃种子（bug A），LLM 变体深挖能否**显著快于或独占地**挖出同根因兄弟 bug（bug B），相比无 LLM 的愚蠢回灌（afl-tmin + 回 corpus 续 fuzz）？

三种结论都算实验成功：**成立**（A 组独占或显著快）/ **无增量**（A、B 都挖出且耗时相近）/ **不成立**（都没挖出，或 A 未挖出 B 挖出）。只有「成立」才触发 1.7.0 立项。

## 2. 靶子

### 2.1 主实验：注入式 bug 对（完全盲，无记忆污染）

- **为什么注入**：CVE-2024-2961（glibc iconv）2024-05 披露、writeup 全网可见，模型大概率背过——「找到同族分支」可能只是训练记忆而非变体分析能力。注入靶 ground truth 完全受控、零记忆污染。
- **靶程序**：真实小型 C 解析器（500~3000 行、输入格式清晰、可 afl-cc 编译；选定后记在 §5）。
- **注入方式**：手工 patch 注入一对同根因兄弟 bug：
  - bug A（种子，给系统）：某字段解析处缺长度校验的越界写；
  - bug B（隐藏，判定用）：同文件另一字段的同模式越界写；触发输入不同、栈指纹不同。
- **边界声明**：合成 bug 只回答「机制成不成立」，不回答「对真实 0day 有效」。外推时报告必须带此声明。

### 2.2 参考实验：glibc iconv（带污染声明，权重低）

- bug A：ISO-2022-CN-EXT SS2 分支（`\x1b$*H`，CVE-2024-2961 的已知一半）；bug B：同文件 SS3 家族（`+I`~`+M`，同一 CVE 补丁修的另一半）。
- harness：ASan + afl-cc 编译「读文件 → iconv UTF-8→ISO-2022-CN-EXT」，种子稳定触发 ASan 堆越界。
- **污染声明**：此组结果可能含训练记忆成分，仅作机制走通旁证，不作立项依据。

## 3. 三组对照（两靶同构执行）

| 组 | 做法 | 预算/时长（先到先停） |
|---|---|---|
| A：LLM 深挖 | 独立会话（DeepSeek API）。输入：种子 crash + ASan 报告 + 源码访问。**无任何 bug B 提示**。按深挖流程驱动：根因结构化（站点/控制字节/bug_class 假设/相邻路径假设）→ 变体生成（直接变体 3-5 + 语料变体 ~20）→ 验证门（直接变体须崩溃且栈指纹≠种子；语料变体须 afl-showmap 出新边）→ 分流 | ≤15 万 token 或 ≤3 小时 |
| B：愚蠢回灌 | afl-tmin 最小化种子 → 回 corpus-in → afl-fuzz 裸跑 | 3 小时 |
| C：空基线 | 同 harness + 普通种子（不含 crash 回灌）裸跑 | 3 小时 |

## 4. 判定标准（锁定，跑后不改）

- **主指标**：产出触发 bug B 路径的输入。判据 = ASan 栈指纹 ≠ 种子 **且** 人工复核确认命中注入的 bug B 分支（两条件同时满足）。
- **假阳性**：新 crash 但栈指纹与种子相同 → 不计入主指标，单独计数。
- **通过（=立项触发）**：A 组在主实验（注入靶）预算内产出 bug B，且满足以下之一：B 组未产出（独占）；或 A 产出耗时显著短于 B（< B 的 1/2）。
- **无增量**：A、B 均产出且 A 耗时 ≥ B 的 1/2 → 结论「愚蠢回灌即可，LLM 无增量」。
- **不成立**：A 未产出（无论 B 是否产出）。
- **次指标记录**：A 组 token 消耗；B/C 组 execs 与耗时；各组假阳性数。

## 6. 实验结论（2026-09-03 跑出，数据归档 `tmp/exp-crash-variant/`）

### 6.1 靶与注入

- 靶程序：cJSON v1.7.18（单文件 3143 行，真实 JSON 解析器）。
- 注入（同根因族：定长全局缓冲写入无边界检查）：
  - bug A（种子）：`utf16_literal_to_utf8` 的 `escape_track[64]`（cJSON.c:733），>64 个 `\u` 转义越界写；
  - bug B（隐藏）：`parse_object` 的 `key_audit[256]` memcpy（cJSON.c:1705），对象键累计 >256 字节越界写。
- 注入教训（记录在案）：初版用 `static` 且只写不读，**-O1 起被 DSE 整个消除**（-O0 崩、-O1 不崩）；改非 static 后 -O1 稳定触发。做注入靶必须按 fuzz 实际优化等级（-O1/-O3）验证触发。
- harness：读文件 → cJSON_Parse → cJSON_PrintUnformatted → Delete；afl-clang-fast -g -O1 -fsanitize=address。

### 6.2 各组原始数据

| 组 | 结果 | 首个 bug B 耗时 | 资源消耗 | 崩溃构成 |
|---|---|---|---|---|
| A：LLM 深挖（deepseek-v4-flash） | **产出 bug B** | **63 秒**（变体生成于 step 10 ~80k tokens，验证于 step 11 ~92k，预算 150k 内） | 总 157,913 tokens / 63s | 1 个变体 1 次命中，0 假阳性；路径：复现种子→定位 escape_track→`grep "static.*\["`扫同模式定长缓冲→锁定 key_audit→构造累积键输入→验证。轨迹零接触人工验证文件 |
| B：愚蠢回灌 | 产出 bug B | **1,393,696 ms ≈ 23.2 分钟** | 2,229,889 execs / 3h | 34 崩溃 = 27×bug B + 7×bug A（种子同族） |
| C：空基线 | 产出 bug B | 1,931,559 ms ≈ 32.2 分钟 | 2,212,074 execs / 3h | 26 崩溃全是 bug B；**3h 未出 bug A**（65 个结构化 `\u` 转义对变异确实难） |

### 6.3 判定（按 §4 锁定标准）

**成立**。A 预算内产出 bug B（栈指纹 `parse_object:1705` ≠ 种子 `utf16_literal_to_utf8:733`，人工复核命中注入分支），且 A 耗时 63s < B 耗时 1394s 的 1/2（697s）——显著快于愚蠢回灌，约 **22 倍**。

### 6.4 对结论的诚实边界（必须随结论一起读）

- **样本量警告（§5）**：单一 bug 家族、单次实验、单模型（deepseek-v4-flash）。结论限「机制成立」，不外推「普遍有效」。
- **LLM 的增量是速度不是独占**：愚蠢回灌 23 分钟也挖到了 bug B。在 execs 便宜（本靶 ~205/s）的目标上，fuzz 的暴力并非不能打「计数型」bug；LLM 的 22 倍速度差在慢目标（真实二进制常 <10/s，23 分钟等效放大到天级）和结构更硬的 bug 上才有真实价值——C 组 3h 未出 bug A 是这一侧的旁证。
- **LLM 的不可替代环节在「指方向」而非「跑验证」**：A 组 63 秒里大部分是读源码，变体一击即中（1 变体 1 命中）；它做的是把「同根因族在哪」这个问题用源码理解直接回答，绕开了变异的盲搜。
- **token 预算超支细节（记录在案）**：A 组驱动循环在 step 14（收尾保存工件）越过 150k 预算被驱动器中止（final=TOKEN BUDGET EXHAUSTED）；但 bug B 的发现与验证发生在 step 10-11（~80-92k tokens，预算内），判定不受影响。

### 6.5 对 1.7.0 的建议

**立项：crash-triager 深挖模式**（实验通过，按既定决策执行）。落地要点直接取自实验观察：

1. **深挖模式 = 源码理解驱动的变体分析**，不是「LLM 帮忙 fuzz」。A 组有效动作序列（复现→根因定位→同模式扫描→定向构造→验证门）原样写进 crash-triager 深挖模式纪律；关键算子是「按根因特征 grep 同族代码模式」（本例 `static.*\[` + 审计/跟踪语义），不是盲目生成输入。
2. **验证门保持硬标准**：新崩溃类 = 崩溃且栈指纹≠种子，防假阳性污染 research_events（1.6.1 风险评估的头号毒点）。
3. **深挖触发闸门**：只对「PC 可控 / 高价值 bug_class / 有源码可读」的崩溃类开放，控制 token（单次深挖预算参照本实验：~150k tokens 上限）。
4. **不回灌替代 fuzz，而是与 fuzz 并行**：实验显示愚蠢回灌 23 分钟也能出——深挖模式的价值定位是「在 fuzz 还在盲搜时先把同族揪出来」，两者并行而非互替；回灌语料变体仍按原设计走 afl-showmap 新边验证门。
5. **样本量债务**：本结论基于单一 bug 家族。1.7.0 实现后 dogfood 应在第二个独立 bug 家族上复测（建议真实 n-day 同族对，而非注入靶），再考虑写进专家库。

## 7. 1.6.2 dogfood：第二 bug 家族复测（glibc iconv / CVE-2024-2961）

> 目的（roadmap 1.6.2 锁定）：①还 1.6.1 §6.5-5 的样本量债务——深挖模式（crash-triager.md 制品原文驱动）在第二个独立 bug 家族上复测；②裁决 A/B/C 接线方案（A=零接线跑通则盖棺）。**记忆污染声明**：CVE-2024-2961 公开披露、模型可能背过 writeup——本组结论权重低于 1.6.1 注入靶，仅作机制复现旁证。

### 7.1 靶场

- 环境：zhishi-env-fuzz 容器，系统 gconv 模块 `ISO-2022-CN-EXT.so` 替换为 2.39-0ubuntu8 有漏洞版（patched 版备份对照——patched 下种子不触发，对照成立）；
- harness `lab_convert.c`：读文件 → iconv UTF-8→ISO-2022-CN-EXT，32 字节输出缓冲 + 16 字节 guard；越界写命中 guard 即打印 `CRASH oob=<guard字节>` 并 abort。**guard 字节 = 分支物理证据**：SS2 分支尾 `2A 48`（`$*H`），SS3 分支 `2B 49~4D`（`$+I..M`）；
- 种子（bug A）：`A + 12×中(U+4E2D) + U+4E0F`（CNS11643 plane 2）→ `CRASH oob=2A480000`（SS2 分支）；
- 源码：glibc-2.39 发布标签（修复前）的 `iso-2022-cn-ext.c`——注意 `release/2.39/master` 分支已是带补丁版（三个块都有检查），实验用错源码会整个作废，记录在案。

### 7.2 两轮运行

| 轮 | 配置 | 结果 | 分析 |
|---|---|---|---|
| 1 | 模式原文 + 150k 累计 token | **预算耗尽未产出**（14 步 / 33s / 158,868） | 方向全对（step 12 识别种子结构与 SS2 根因，step 13 明确找 SS3 平面字符），死在扫描阶段。暴露两个真问题：①累计口径下 150k 有效上下文仅 ~25k，iconv 靶步数需求 > cJSON 靶；②模式缺扫描输出收敛纪律（上万行 probe 输出灌上下文）。**卫生事故**：验证文件 check-b*.bin 误留工作区被 `xxd` 偷看（本论作废主因之一，记录在案） |
| 2 | 模式+扫描收敛纪律（161b050）+ 300k 累计 | **产出 SS3 变体**（发现于 step 18 ≈242k 累计 / 全程 84s） | `variant-ss3.bin` → `CRASH oob=2B490000`（plane 3 `$+I`）；`variant-ss3-p4.bin` → `2B4A0000`（plane 4 `$+J`，与人工验证文件独立重合）；收尾保存工件时再撞预算帽被驱动器中止（finish 未调用，工件已落盘） |

### 7.3 判定（判据同 1.6.1 §4，人工复核）

**通过**。①变体崩溃（SIGABRT + guard 污染）；②指纹 ≠ 种子（`2B49`/`2B4A` ≠ `2A48`）；③人工复核命中 SS3 未检查分支（guard 字节 `$+I`/`$+J` 即 SS3 指派序列尾字节，iso-2022-cn-ext.c SS3_mask 块）；④**污染审计**：第二轮轨迹全程未读/未运行 check-b*.bin（仅出现于 ls 列表），未读第一轮轨迹内容，SS3 字符来自其自主 probe 扫描——独立发现成立（plane-3 字符甚至不在人工预验清单里）。

### 7.4 裁决与结论

- **A/B/C 接线裁决：A（零接线）盖棺**。两轮均在无任何方法论注入下完成根因结构化与同族定位；第二轮修的是输出纪律（机制内改进），不是知识接线。B/C 维持不立项。
- **机制在第二家族复现**：深挖模式（复现→根因结构化→同族扫描→定向构造→验证门→分流）原样有效；动作序列与 1.6.1 同构（根因 →「同模式扫描」→ 定向构造 → 一击即中）。
- **遗留记录**：①累计 token 口径的预算对多步深挖偏紧，委派方定预算时按靶步数估（cJSON ≈92k，iconv ≈242k 发现点）；②驱动器在预算帽前给收尾留余量（两轮都死在保存工件阶段——artifact 已落盘所以无实际损失，但正式产品化时驱动逻辑应「接近预算即要求立即 finish」）；③验证文件不得放实验工作区（第一轮教训）；④iconv 靶的记忆污染声明持续有效，本组权重低于注入靶。

### 7.5 样本量债务状态

两个独立 bug 家族（cJSON 注入对 / glibc iconv 真实 n-day）均复现成功。**债务降级但未清偿**：写进专家库前建议在首个真实用户场景中自然验证一次（非实验编排），届时按 `zhishi expert promote` 流程人审沉淀。
