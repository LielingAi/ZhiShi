# 实验：崩溃变体深挖——LLM 变体生成 vs 愚蠢回灌（1.6.1）

> 状态：**标准已锁定（2026-09-03，先于实验提交入库）**。判定标准（§4）跑后不改；实验结论跑出后补在 §6。
> 缘起：借鉴 colony / Fuzzillai 评估中，「崩溃变体深挖闭环」（crash → 根因 → 变体 → 验证 → 回灌）被列为 1.7.0 候选。但反证发现三条软肋：①zhishi 真实使用数据里 fuzz 断链从未实际造成损失；②Fuzzillai 的同类闭环（EBG-Crash）机制走通但新 bug = 0，是最接近的对照实验且结果为负；③存在零 LLM 成本基线（afl-tmin + 回灌），LLM 增量从未被测量。故先实验后立项：**本实验裁决「LLM 变体深挖相对愚蠢回灌有无增量」，通过才进 1.7.0**。

## 1. 实验问题

> 给定一个崩溃种子（bug A），LLM 变体深挖能否**显著快于或独占地**挖出同根因兄弟 bug（bug B），相比无 LLM 的愚蠢回灌（afl-tmin + 回 corpus 续 fuzz）？

三种结论都算实验成功：**成立**（A 组独占或显著快）/ **无增量**（A、B 都挖出且耗时相近）/ **不成立**（都没挖出，或 A 未挖出 B 挖出）。只有「成立」才触发 1.7.0 立项。

## 2. 靶子

### 2.1 主实验：注入式 bug 对（完全盲，无记忆污染）

- **为什么注入**：CVE-2024-2961（glibc iconv）2024-05 披露、writeup 全网可见，模型大概率背过——「找到同族分支」可能只是训练记忆而非变体分析能力。注入靶 ground truth 完全受控、零记忆污染。
- **靶程序**：真实小型 C 解析器（500~3000 行、输入格式清晰、可 afl-cc 编译；选定后记在 §5）。
- **注入方式**：手工 patch 注入一对同根因兄弟 bug：
  - bug A（种子，给系统）：某字段解析处缺长度校验的越界写；
  - bug B（隐藏，判定用）：同文件另一字段的同模式越界写；触发输入不同、栈指纹不同。
- **边界声明**：合成 bug 只回答「机制成不成立」，不回答「对真实 0day 有效」。外推时报告必须带此声明。

### 2.2 参考实验：glibc iconv（带污染声明，权重低）

- bug A：ISO-2022-CN-EXT SS2 分支（`\x1b$*H`，CVE-2024-2961 的已知一半）；bug B：同文件 SS3 家族（`+I`~`+M`，同一 CVE 补丁修的另一半）。
- harness：ASan + afl-cc 编译「读文件 → iconv UTF-8→ISO-2022-CN-EXT」，种子稳定触发 ASan 堆越界。
- **污染声明**：此组结果可能含训练记忆成分，仅作机制走通旁证，不作立项依据。

## 3. 三组对照（两靶同构执行）

| 组 | 做法 | 预算/时长（先到先停） |
|---|---|---|
| A：LLM 深挖 | 独立会话（DeepSeek API）。输入：种子 crash + ASan 报告 + 源码访问。**无任何 bug B 提示**。按深挖流程驱动：根因结构化（站点/控制字节/bug_class 假设/相邻路径假设）→ 变体生成（直接变体 3-5 + 语料变体 ~20）→ 验证门（直接变体须崩溃且栈指纹≠种子；语料变体须 afl-showmap 出新边）→ 分流 | ≤15 万 token 或 ≤3 小时 |
| B：愚蠢回灌 | afl-tmin 最小化种子 → 回 corpus-in → afl-fuzz 裸跑 | 3 小时 |
| C：空基线 | 同 harness + 普通种子（不含 crash 回灌）裸跑 | 3 小时 |

## 4. 判定标准（锁定，跑后不改）

- **主指标**：产出触发 bug B 路径的输入。判据 = ASan 栈指纹 ≠ 种子 **且** 人工复核确认命中注入的 bug B 分支（两条件同时满足）。
- **假阳性**：新 crash 但栈指纹与种子相同 → 不计入主指标，单独计数。
- **通过（=立项触发）**：A 组在主实验（注入靶）预算内产出 bug B，且满足以下之一：B 组未产出（独占）；或 A 产出耗时显著短于 B（< B 的 1/2）。
- **无增量**：A、B 均产出且 A 耗时 ≥ B 的 1/2 → 结论「愚蠢回灌即可，LLM 无增量」。
- **不成立**：A 未产出（无论 B 是否产出）。
- **次指标记录**：A 组 token 消耗；B/C 组 execs 与耗时；各组假阳性数。
