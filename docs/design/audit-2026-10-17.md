## 3. BUG 与隐患（按严重度）

### P1 · EnvPanel 绕过环境准入闸

`EnvPanel.tsx` 行点击直接 `switchEnv` → 服务端 `handleEnvironmentSelect`
（`admin-api.ts:4443-4448`）只校验 workspace/选择合法/busy，**不校验环境启动态**。
结果：从 2.0 环境面板点**已停止**环境可进入其冷线——与产品红线「已停止不可
进入（先启动）」矛盾（正门行点击的准入闸拦住了，面板这条路径漏了）。
**修法**：EnvPanel 点击前复用 `accessGate` 判定（既有 `gateToast` 文案）。

### P2 · xfer 目录语义未定义

`fromPath` 为目录时 `docker cp` 整目录进临时子目录、`putFileToEnv` 再拷到
`toPath`——形成嵌套目录而非"目录合并/改名"，行为未定义。**修法**：v1 限传
文件（源 stat 校验非目录），目录传输留后续。

### P2 · merge 两步非原子（可恢复）

`renameEnvSessionEnvId`（映射迁移）在 `atomicModifyConfig`（摘登记）之前；
若后者失败，映射已迁移、drop 条目仍在——两操作均幂等，重跑合并可收敛，
但中间态短暂"两处都指向 keep"。**修法**：接线测试覆盖失败回滚路径即可。

### P3 · prune 的 VM 探活 N 次 spawn

`handleEnvironmentPruneList` 循环内每 vm 候选调一次 `vmEnvPs`（vmrun 列表
进程）。候选多时为 N 次进程启动。**修法**：提到循环外取一次 ps 快照。

### P3 · StatusBar 残留小冗余

状态栏仍调 `buildEnvStrip`（6 段上限排序）只为取当前行状态点——直接按
`envKey` 查 `envs`/`running` 即可。纯清理项。

### P3 · WebView2 清扫并发边界（文档化即可）

启动时清扫非当前版本缓存目录；若同一 LOCALAPPDATA 下有**两个安装实例**
同时运行（罕见），清扫可能删掉另一实例的旧版本缓存目录（后果=对方下次
改新缓存重建，无数据损失）。
