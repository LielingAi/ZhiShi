# 1.1.9 设计：TUI 优化——性能基本盘 + 子代理可见性

> 2026-08-21 立项。TUI 为完全自研（`src/cli/tui/v2/`，无第三方 TUI 依赖）。
> 候选池来自全量代码摸底（每项带行号证据），本版只做「本版范围」内的项；
> 池里其余项列在文末备查，不在本版动。

## 本版范围

### 一、性能四件

**P1 流式渲染 O(n²) → 尾部增量（主菜）**
- 现状：`chat:message-chunk` → `app.ts:475` repaintBlocks → `renderAssistant`
  → `blocks/message-block.ts:44` `renderMarkdown(累计全文)`；随后
  `terminal-writer.ts:269` `wrapCache.delete(id)` → 全文逐 grapheme 重折行。
  50KB 回复 × 几百 chunk = 每帧全量重算，越到尾部越贵。
- 修法：streaming 块走尾部增量——已折行的稳定前缀（除末行外的 visual
  lines 不再变）缓存住，每 chunk 只重算末段；markdown 同理解析尾段。
  注意保持非流式路径（回放/静态块）现状不动。
- 验收：同一长回复任务前后对比帧耗时（可写微基准：模拟 N chunk 重放，
  对比 P95 帧耗时）；全量 TUI 测试绿。

**P3 Intl.Segmenter 单例化（一行）**
- 现状：`ansi.ts:165-169` `graphemes()` 每次 `new Intl.Segmenter`，被
  wrap/truncate/宽度计算全链路调用（构造比切分贵）。
- 修法：模块级单例复用（无状态可共享）。

**P4 chrome 高度变化的全屏重绘收窄**
- 现状：`app.ts:1566` renderChrome 每键/每事件调 `setChrome({inputHeight})`；
  高度一变 `invalidateFrame()` + 同步 `flush()`（`terminal-writer.ts:209-213`），
  输出区 diff 基线全废——补全过滤时边打字边全屏刷。
- 修法：input 区高度变化只 invalidate input 区；输出区用「行内容+绝对行号」
  复合 key 保未动行 diff；flush 降级为 request（16ms 合帧）。

**P5 resize 防抖**
- 现状：`entry.ts:131-134` 每个 resize 事件直接全量重折行 + 同步 renderFrame
  （`terminal-writer.ts:330-342`），拖窗口一秒几十个事件。
- 修法：resize 走 FrameScheduler 合帧（~50ms 防抖），期间只记最新尺寸。

### 二、子代理可见性

**U1 死按钮（活 bug）**
- 现状：`blocks/dividers.ts:59` 渲染「要我切过去吗？(y)」，
  `event-reducer.ts:384` 设了 switchHook，但按键路由无任何处理——按 y 把
  字母打进输入框。
- 修法：输入态空编辑器时按 y 且存在待切换的 subagent 结论 → 触发对应
  session switch；注意与正常输入 y 的歧义判定（仅空编辑器 + 有待切结论时
  拦截）。

**U2 `/tasks` 面板**
- 现状：`bg-tasks.ts:8` 注释承诺 `/bg` `/tasks`，均未实现；子代理可见性
  只有状态栏一小段（窄终端被 `chrome.ts:141-143` room 检查静默丢弃）。
- 修法：`/tasks` overlay（复用 queue overlay 模式）：列出 tasks（运行中/
  完成）+ bgProcs，可选中查看结论详情。`/bg`（当前 turn 转后台）本版不做，
  注释承诺收敛到已实现的面板。

### 三、小 UX 三件

- **U3 Esc 清草稿可恢复**：`app.ts:607-617` Esc 清空前把草稿压入一次性
  恢复槽，再按 ↑ 或 Ctrl+Y 找回；不实现完整 undo 栈（留观察）。
- **U6 回看键位接线**：PgUp/PgDn 从固定 ±10 行（`app.ts:620`）改调
  `viewport.ts:88 scrollPages(±1)`；`scrollToTop`（terminal-writer.ts:289）
  绑键（g/Ctrl+Home 跳顶、G/Ctrl+End 或现有 Esc 回底）。
- **U7a 粘贴补补全**：`app.ts:494` paste 后补 `updateLiveCompletion()`
  （普通击键路径有，`app.ts:659`）。

  （`app.ts:1672-1688`）的状态栏 compose 重复合一处。

## 明确不做（本版）

- **H1 app.ts 拆分**（1727 行 god object）：与渲染管线改动并行会搅 diff，
  归下版第一件事；届时照 1.1.7 手法拆 slash/overlay/gate 三块。
- U2 的 `/bg`（turn 转后台）、U4 @ 文件补全、U5 工具卡多展开、
  U7bc 大粘贴折叠/图片粘贴、U8 杂项（Ctrl+C 双击确认、token 展示、
  thinking 展开）、P1/P2/P6/P7 外的性能长尾——全部进候选池备查。

## 铁律

- 性能项必须有前后对比数据（微基准或实测），不靠感觉。
- 全量测试绿是每步门槛；TUI 行为变化（键位、提示文案）逐条过验收。
- 渲染正确性优先于性能：增量路径有任何疑义的位置回退全量重算。
