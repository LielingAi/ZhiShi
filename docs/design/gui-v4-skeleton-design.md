# GUI v4 骨架布局改造设计稿

> 状态：设计稿 v1（2026-10-16）。前置：v4 操作语法稿（proto-v4，WREN 已拍"满意"）、
> `gui-v4-capability-audit.md`（74 项能力底账）、1.9.11 首批五批已落地。
> 立项动机：首批刻意没动布局，真机反馈"没变动"——操作语法要长进骨架里，
> 不是只挂在交互细节上。**本稿评审通过后分批实施；每批带门禁与真机验收。**

## 0. 一句话

**把"操作系统操作感"做进布局**：中心永远只有当前线，对象驻留在可收放的检查面板，
一切动作走命令中枢，系统状态与 Esc 语义沉底——环境管理退到"正门"，不再是常驻侧栏。

## 1. 现状骨架（1.9.11）

```
┌──────────┬──────────────────────────────────────────────┐
│ EnvSidebar│ Toolbar（env锚/mission/历史/auto-run/研究/决策）│
│ (常驻    │ MainArea ────────────── ArchivePane(≥1280分屏) │
│  环境管理)│  会话流（虚拟列表）      │ 研究档案链            │
│          ├──────────────────────────────────────────────┤
│          │ StatusBar（env锚/phase/队列/ctx/模型/⛁/主题）  │
│          │ InputArea（chips+textarea+发送）               │
├──────────┴──────────────────────────────────────────────┤
│ 覆盖层：Tasks / Queue / Lines / CrashInspector / Overlay  │
│ / BoundaryModal / DecisionModal / Modal×17 / Toast        │
└───────────────────────────────────────────────────────────┘
```

问题：环境管理常驻左侧占 ~15% 宽度（单环境深潜 DNA 的反面）；档案分屏只在宽屏出现；
任务/线/检查器全是"浮层叠叠乐"；命令入口一半在输入行（/）一半在 Ctrl+K；
系统状态散在 Toolbar 与 StatusBar 两处。

## 2. 目标骨架（v4）

```
┌──────────────────────────────────────────────────────────────┐
│ menubar：◣ zhishi · line/x · mission徽章 · 共享 │ ctx tok env 钟│  30px
├──────────────────────────────────────────────┬───────────────┤
│                                              │ 检查面板       │
│   会话流（当前线，唯一主角，≥60% 宽度）          │ （可收起）：    │
│   虚拟列表/折叠/锚点高亮（1.9.11 全保留）        │ 任务·线·档案·  │
│                                              │ 检查器 四页签   │
├──────────────────────────────────────────────┴───────────────┤
│ 状态行：◐运行/⏸/○ · 队列 · 模型 │ ⛁后台段 │ ✓回执 │ Esc:停  │  26px
│ wren@env ❯ 输入行（说话/:/@，chips）                            │
└──────────────────────────────────────────────────────────────┘
                  Ctrl+K → 命令中枢（覆盖一切动词+对象）
                  正门（启动/无环境时）：选/建环境，两动词
```

四根柱子：
1. **中心唯一主角**：会话流永不被挤（信息流密度功能全保留）
2. **右侧检查面板**：任务/线/档案/检查器 四页签常驻可收起（draggable splitter）——
   覆盖层从"浮层叠叠乐"减到只剩命令中枢/边界/决策三 modal 族
3. **命令中枢** Ctrl+K：统一 `/` 动词与对象补全（输入行的 `/` 前缀保留为同引擎快捷入口）
4. **状态行沉底**：运行态/后台段/**动作回执**/此刻 Esc 语义——回执从 Toast 迁此

## 4. 交互语法落点（v4 定调回顾）

- **对象一等公民**：检查面板四页签 = 四个对象族；流内 chips/锚点可点直达检查器
- **动词直达**：命令中枢统一动词+对象（1.9.11 的 slash-objects 引擎原样上移）；
  输入行 `/` 与 Ctrl+K 是同一引擎两个门
- **因果即时**：回执沉底状态行（✓ xxx 2200ms 自隐）——Toast 组件退役改薄封装
- **危险有仪式**：越界/决策/终止确认 modal 族保留，红框唯一性不动

## 5. 关键决策点（WREN 拍板）

1. **EnvSidebar 去留**：目标骨架里环境管理退到"正门"（启动屏/`:env` 唤起）。
   留一条 40px 细栏 vs 完全退到正门+命令？——建议完全退（单环境深潜 DNA），多环境党走命令中枢。
2. **档案分屏**：宽屏 6/4 分屏（现状）改为检查面板内页签，还是保留"宽屏自动分屏"特例？
   ——~~建议保留特例（档案看板信息量大，分屏是既有爽点），页签是窄屏/收起态归宿。~~
   **修订（2026-10-16 WREN 真机拍板，V4-S3）**：宽屏分屏退役——真机四列排版乱
   （档案分屏夹在会话流和 SidePane 之间），档案唯一落位 = SidePane「档案」页签
   （宽屏窄屏同一形态）。原"保留分屏"决策作废；`main-split`/`arc-divider`/
   抽屉/`flash` 定位高亮随之整体拆除，入口（研究按钮/→V3 徽章/锚跳流）全部改接
   `openSidePane('archive')`。
3. **回执与 Toast**：Toast 退役改状态行回执，还是 Toast 保留做"重要通知"、回执只做动作确认？
   ——建议回执接全部动作确认，Toast 只留错误/越界过期这类需留意的（双轨）。
4. **正门形态**：启动即正门（每次启动选环境）vs 记住上次现场直接进、正门走命令唤起？
   ——建议后者（resume 语义：启动回昨天的现场），正门只做"无环境/新建"场景。

## 7. 验收判据

1. 74 项能力逐项可在目标骨架中指到落位（功能不丢）
2. 全部动作 ≤2 次输入可达（命令中枢统计验证）
3. 每个动作 100ms 内可见回执（状态行）
4. 无鼠标可完成：发消息/切线/停 turn/看任务/看档案/批越界
5. 真机走查六场景（开局进现场/中途切线/战役观察/崩溃深挖/越界审批/收尾提取）
