# 1.1.7 技术方案定稿

> 2026-08-21 立项。定位：纯技术债版，无用户可见功能。
> 最高铁律：**纯搬移、不改行为**——每个 commit 全量测试绿，既有测试断言一行不改；
> 重构顺手改逻辑是还新债的最短路径，禁止。
> 背景数据（2026-08-21 实测）：`index.ts` 13041 行、`admin-api.ts` 7802 行；
> `chat-engine.ts` 导出 24 函数、import 方仅 `admin-api.ts` 与 `index.ts` 两家；
> `src/` eslint 零问题、depcruise 0 errors。

---

## ① 文件 IO 纪律统一

**问题**：`withFileLock` + tmp+rename 已是写盘惯例（SessionStore / loop/session /
env-sessions / admin-config 等），但仍有人裸读写 `~/.zhishi` 可变状态文件——
`environment/selection.ts`（env-selection.json）是确认的首犯（1.1.6 核实时记录）；
多 zhishi 实例共用同一数据目录时，裸读-改-写存在丢更新窗口。

**做法**：
1. 逐个审查 `src/server` 下 `readFileSync/writeFileSync` 使用点（清单见下），
   **只改「写 `~/.zhishi` 可变状态 JSON」的点**；读 bundled 资源 / skills /
   静态文件的不动；已有锁的不动。
2. 统一为：`withFileLock` 锁内读-改-写 + tmp+rename 原子替换（照
   `environment/env-sessions.ts` 的 `mutateEnvSessionsMap` 范本）。
3. 已知候选：`environment/selection.ts`（必改）；其余以审查结果为准
   （`memory/store.ts`、`memory/distill.ts`、`loop/bg-registry.ts`、
   `intel/sync.ts`、`mcp-oauth/token-manager.ts` 等待甄别——注意甄别
   「写数据目录」vs「写别处」，别把 bundled 资源的读取卷进来）。

**验收**：改造点各配一个并发写不丢更新的单测（范本：
`env-sessions.unit.test.ts` 的并发写用例）；全量回归绿。

## ② 引擎状态收拢成类

**问题**：`chat-engine.ts` 的可变状态是一坨模块级 `let`（sessionId / messages /
queue / steering / busy / currentAbort / boundSessionMetaId / currentEnvKey /
systemInitInfo / messageSeq / streamingAssistantId …），状态边界只能通读全文件
才知道；cron 与 TUI 共用单例的耦合（1.1.6 踩过边）埋在各个函数里不可见。
这是 2.0「多环境并行」的硬前提。

**做法（机械收拢，行为零变化）**：
1. 新建 class `ChatEngine`：模块级 `let` 全部搬为私有字段；24 个导出函数
   变方法；文件内函数间调用改 `this.`。
2. 文件底部：`const defaultEngine = new ChatEngine()` + 按原签名导出
   facade 函数（逐个委托 `defaultEngine`）——`admin-api.ts`/`index.ts`
   **调用点零改动**。
3. 模块级 `initPiChatEngine(agentDir)` 等初始化入口保留原签名，内部委托。
4. 明确**不做**：不解 cron/TUI 共用单例的语义耦合（归 2.0）；不改任何
   判断/时序；不重排函数。

**风险点**：`chat-engine.unit.test.ts` 的 mock 方式（mock 依赖模块而非引擎
内部状态）决定测试是否零改动——实施时先确认；若测试摸了模块内部状态，
允许改测试的接入方式但**不允许改断言**。

**验收**：全量测试绿（断言零改动）+ typecheck + depcruise 无新违规。

## ③ god file 绞杀拆分（timebox）

**问题**：`index.ts` 13041 行——HTTP 路由、cron、会话管理、sse 全堆一处，
每个版本都要动它。`admin-api.ts`（7802 行）本身是 handler 包，拆分优先级低。

**做法（绞杀式，每抽一块一个 commit）**：
1. 第一刀 **cron**：定时任务系统整段抽出 `src/server/cron/`（最内聚，
   与 1.1.6 的耦合点最近，抽走后 2.0 解耦也好做）。
2. 第二刀 **sessions 路由**（/sessions CRUD + switch）抽 `src/server/routes/`。
3. 第三刀 **路由表集中**：`routeAdminApi` 的 if 链收敛为路由登记表。
4. 抽到哪算哪——**timebox：`index.ts` ≤ 8000 行收手**，剩余的归日常随做随拆。

**验收**：行数达标 + 全量测试绿 + VM 在线时 `npm run smoke` 5/5。

## 顺序与理由

① → ② → ③。①最小且独立，先落袋；②只动一个文件，最收敛；③范围最大
放最后，timebox 兜底可伸缩。每步完成后：`npm run typecheck` + `npm test`
全绿才进下一步。
