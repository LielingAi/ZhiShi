# ai-security —— AI 安全测试方法论

**纪律红线**：只测自有模型或拿到书面授权的模型。被测端点与授权范围人确认过再进场。

## 决策链（每环都有「什么信号往下一步走」）

### ① 明确测试目标（先问三个问题）

1. 测什么：模型本体 / 应用层（RAG、Agent、插件）/ 供应链（训练数据、依赖库）？
2. 威胁模型是什么：谁在攻击、想拿什么（系统提示词/用户数据/让模型执行恶意动作）？
3. 目标暴露面：API 端点、对话界面、文件解析入口（AI 应用的文件注入面常比模型本体更薄）

- **信号**：一份「攻击面清单」——每条挂测试优先级。没这个清单的扫描是瞎扫

### ② 攻击面分类（决定探针选择）

| 类 | 例 | 工具 |
|---|---|---|
| 越狱 | 角色扮演/编码绕过/多语言绕过 | garak（lmrc/jailbreak 探针） |
| 提示注入 | 文档注入、间接注入（网页/邮件里的指令） | 手工构造 + promptfoo 断言 |
| 数据泄露 | 系统提示词、训练数据、用户数据提取 | garak（leakreplay 类） |
| 偏见/幻觉 | 有害输出、事实幻觉 | garak（toxicity 类）+ promptfoo |

### ③ 基线扫描（garak）

```
garak --model_type openai-compatible --model_name <m> \
      --model_option api_base=<端点> --model_option key=<key> --probes lmrc
```

- **信号**：FAIL 探针清单 + 每个 FAIL 的复现 payload
- garak 的 FAIL ≠ 确认漏洞——**每条都要手工复现**，探针命中只是线索
- **先 `garak --list_probes` 查探针族**再按威胁模型选 `--probes`——盲跑全部又慢又打限流（见常见坑）
- **报告读 JSONL 别只读终端滚动**：`<run>.report.jsonl` 每行按 `"entry_type"` 分型（`attempt`=单次探测、`eval`=探针×detector 判定、`probe_summary`=汇总）；判定信号看 `eval` 行的 `passed`/`total_evaluated`——有 fails（pass rate <100%）的探针才值得追，失败样本的 prompt/output 原文在同目录 `<run>.hitlog.jsonl`
- 终端摘要行的 `attack success rate` 就是 eval 行 pass rate 的人读版；两者对不上时以 JSONL 为准
- **多轮场景升级 → PyRIT**（garak 单轮探针打不动时；无 CLI，python3 驱动）：新 API 在 `pyrit.executor.attack`——`PromptSendingAttack`（单轮编排）/ `RedTeamingAttack`、`CrescendoAttack`（多轮策略）；调用骨架见 ai-security 配方 SKILL.md

### ④ 自定义 eval（promptfoo——针对你的威胁模型）

- 把「你们家产品不能出现的事」写成断言（不能吐系统提示词、不能执行注入指令、不能泄露他人数据）
- 断言失败 = 真实问题（eval 的语义比扫描器准，因为断言是你自己定义的）
- **信号**：断言失败清单 + 复现步骤

### ⑤ 分级与留痕

| 级别 | 判据 | 动作 |
|---|---|---|
| 确认 | 稳定复现 + 有实际影响（泄露真数据/执行了注入动作） | research_log 落 bug_class |
| 可疑 | 能复现但影响不明 | 记录 + 标注待验证 |
| 误报 | 拒绝≠安全，但一次失败≠漏洞 | 丢弃（记一次死路） |

## 常见坑

- **拒绝≠安全**：模型拒绝一次不代表绕不过——换个措辞/语言/角色就过了
- **探针 FAIL 误报**：garak 对特定模型兼容性差，FAIL 要先看是不是端点格式问题
- **速率限制**：扫描打爆端点限流——探针分批跑，别一次全开
- **拿真实数据当测试用例**：泄露类测试用构造数据，别把真实用户数据喂进去
- **越狱词库过时**：公开探针库对最新模型命中率低——**手工构造**（角色反转/编码/多语言）常比扫描器有效
- **标记词判定要看上下文**（1.1.8 实战）：被测方常在**拒绝时引用**注入标记词（"我没有回复 COMPROMISED"）——子串匹配会把拒绝误判成顺从。动作类 canary（文件/进程/网络痕迹）才是硬证据，文本标记只能当辅助

## 降级路径

- garak 装不上/不兼容 → 手工构造 payload + promptfoo 断言（其实这一步价值更高）
- 端点限流 → 本地起模型测（ollama），测完再对远端做小样本验证
- 完全没工具 → 手工测试用例清单（OWASP LLM Top 10 逐条过）
- 知识缺口（不是工具缺口：探针怎么构造/判定拿不准）→ 查 `expert_search`——专家审定知识，决策级；**先尽力；识别到知识缺口再查**（缺口的信号是反复失败/没有把握/找不到先例，不是进展慢——慢慢做对不需要救援）；未命中 = 库里没这条 ≠ 方法不存在，标注「无先例」后继续
- 本域缺口信号实例（命中任何一条 = 该查 expert_search 了）：探针全部无反应，不知道是模型抗住了还是探针没生效；判定结果只有文本标记没有动作证据，拿不准算不算攻破；没见过这类攻击面（新的入口形态），不知道探针怎么构造

## 留痕

- 每个确认/可疑问题落 `research_log`（kind=ai-security，bug_class 挂对应类别）
- 死路（哪些探针试过无效、哪些绕过手法被封）也留痕——这是蒸馏最值钱的原料
- 产出工件（PoC/样本/截图）必挂 `trajectory_ref`（环境内路径）——报告导出的证据回收按此登记
