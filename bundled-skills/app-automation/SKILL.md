# app-automation — 任务 skills 化（沉淀 → 执行 → 进化）

你在 ZhiShi 的 AppCraft 能力下工作。核心思想（工作生命宪章 §6）：**能力是工作知识的沉积，不是脚本**。
一个任务被成功完成后，它的做法可以沉淀为 skill——下次执行时默认走确定性快速通道（零 token、
秒级），失效时回到全智能执行（带着 skill 里的知识完成任务）。快速通道是优化，全智能是本体。

## skill 的结构（五段式，蒸馏层是本体）

```
<workspace>/.claude/skills/<name>/
├── SKILL.md      # 本体：目标 / 关键决策 / 参数 / 验收 / 已知坑
├── trace.json    # 可选加速层：编译出的确定性操作序列
└── frames/       # 关键帧截图（可选）
```

**SKILL.md 五段式**（写决策级事实，不写流水账）：
1. **目标**：一句话说清这个任务做什么（"每月导出金蝶销售报表"）
2. **关键决策**：为什么这么做、为什么这样做而不是那样（"导出走'文件→导出'而非快捷键，后者在弹窗态失效"）
3. **参数**：`{{变量}}` 说明（含义、格式、示例值）
4. **验收**：怎么算成功（导出文件出现在数据目录且行数 > 0）
5. **已知坑**：实测踩过的坑及解法（"菜单弹出态 press_key 失效，要用 press_key_global"）

## 工作流一：沉淀（任务完成后，回溯式）

**入口**：一个任务刚被成功完成时。不要问用户"要不要开始录制"——录制是后台机制，
用户不需要知道。你主动提议："这个以后还会做吗？存成 skill？"

1. **回溯提取**：从本会话的消息流收集你刚执行过的 terminator/cuse 工具调用（
   `zhishi appcraft record` 只是工具，用户无感）。
2. **蒸馏写 SKILL.md**（五段式，见上）：
   - 从操作过程提炼关键决策（为什么选这个路径、哪个步骤最容易翻车）
   - 参数化：把日期/金额/文件名等变量抽成 `{{变量}}`，**显式列出清单让用户确认**
     （防敏感数据固化，防误参数化）
   - 验收标准写具体（可检查的状态，不是"看起来完成了"）
   - 已知坑写进去（本次踩过的 + 修复方式）
3. **编译 trace**（可选加速层）：`zhishi appcraft record stop` 的产物，
   存入 skill 目录。回放优先级：确定性优先，但它只是加速层。
4. 告知用户：skill 已可被会话/cron/IM 调用，"以后说一声'跑一下 <任务名>'就行"。

## 工作流二：执行（确定性优先，智能兜底）

用户说"跑一下 X"或定时触发时：

```bash
zhishi appcraft replay <skillName> [--var 月份=2026-06 ...] [--json]
zhishi appcraft replay <name> --dry-run        # 预览不执行
zhishi appcraft replay <name> --yes-high-risk  # 用户批准过高危步骤后放行
```

- **能走快速通道就走**——确定性回放，秒级、零 token。
- **高危审批**：`highRisk` 步骤被拦截（`APPCRAFT_REPLAY_APPROVAL_REQUIRED`）时，
  先把步骤内容和后果告知用户，获明确批准后 `--yes-high-risk` 重跑。不要替用户跳过。
- **无人值守**（cron/Hub）：目标应用未批准时引擎拒绝（`APPCRAFT_REPLAY_UNAPPROVED_APP`），
  引导用户在场跑一次并"允许并记住"。

## 工作流三：失败时的正确姿势（SOP 模式，不是"自愈补丁"）

回放失败**不是异常，是预期内的一种执行路径**：

1. 从失败报告定位步骤索引与原因。
2. **切换到 SOP 模式**：打开 SKILL.md，按五段式知识用全智能完成剩余步骤——
   你有目标、关键决策、参数和验收标准，足够你独立把任务做完。
3. 任务完成后**回写 skill**：把这次的环境变化/新坑写进"已知坑"，
   如需要可重新编译 trace。**skill 越用越准，不是越用越旧**——这是宪章 §6.4 的要求。
4. 回写前把改动呈现给用户确认。

## 红线

- 窗口未找到/已关闭 → 用 `launch_app`/`open_application` 重启目标应用，**禁止退回全屏搜索/全屏截图**。
- skill 是本体，trace 是加速层：**永远不许把"回放成功"当作任务完成的定义——验收标准（SKILL.md 第四段）才是**。
- 高危步骤必须用户明确批准；无人值守只许做被批准的事。
- 沉淀时**显式列出全部字面量参数让用户过目**（防敏感数据固化）。
